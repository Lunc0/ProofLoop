# 规格：层级 Markdown SkillMap 与整块替换 EditPlan

> **阶段：**23 · **版本：**v0.21 · **状态：**已完成
>
> **前置阶段：**[阶段 20：候选内置 SkillMap](20-v0.18-candidate-owned-skill-map.md) · [阶段 21：紧凑 SkillMap 与短编辑锚点](21-v0.19-compact-skill-map.md) · [阶段 22：EditPlan 位置语义与问题-变更分层](22-next-edit-plan-location-semantics.md)

## 1. 目标

以 Markdown 标题树替代现有 paragraph/list 的线性 `bNN` block。每个可编辑 block 是一个标题及其完整子树，ID 由同级序号构成路径：第一个一级标题为 `b1`，其下第二个二级标题为 `b1.2`，其下第四个三级标题为 `b1.2.4`。

模型 edit 只有两种位置语义：以完整 Markdown block 替换一个既有 block，或在一个既有 block 下新增一个子 block。不再允许 anchor、merge、remove、reorder 等位置操作，也不按 rule 类型决定渲染方式。这样对 `b26` 中单条列表规则的修改，必须改写所在的 `## Error Recovery` section，而不会伪装成对相邻段落的替换。

## 2. 范围

### 2.1 SkillMap v3

- 以 ATX 标题（`#` 至 `######`）建立有序树；每个标题 block 的覆盖范围从该标题行开始，到下一个同级或更高层标题之前。ID 是标题树路径 `b<ordinal>(.<ordinal>)*`。
- 标题路径按最近的前置、更高层标题建立；标题层级跳跃不额外猜测或补造虚拟节点。文档必须有可用的一级标题，才能产生可编辑 map。
- 对模型持久化/暴露的 map，每个 block **只**保留 `block_id`、标题文本、标题层级与 `permission`。行号、文本范围、段落/list 类型、layer、证据及其他审计字段不进入 SkillMap；renderer 在内存中重新解析范围。
- front matter 与首个一级标题之前的内容不作为可编辑目标。权限仍沿用 `locked`、`guarded`、`evolvable`、`experimental`；编辑 target 或新增 parent 的任一祖先/后代为 locked 时，操作被拒绝，避免绕过保护。

### 2.2 替换式 EditPlan v2

替换 edit 固定含一个 `target_block_id` 与一个 `replacement_markdown`；`replacement_markdown` 是该标题 block 的完整替换文本，首个非空行必须是与目标同级的 ATX 标题，后续不得出现同级或更高层标题。它可以包含更低层的子标题。

新增 edit 固定含一个 `parent_block_id`、可选的 `after_block_id` 和一个 `new_block_markdown`。新增根标题不被支持：新 block 的首个标题必须恰好比 parent 低一级；`after_block_id` 如存在，必须是 parent 的直接子 block，新增 block 放在其后；省略时追加到 parent 的末尾。因此模型能在 `b1` 下新增一个并列二级标题，也能在 `b1.2` 下新增一个并列三级标题。

- `operation` 只允许 `replace_block` 或 `add_block`。删除 `target_block_ids`、`placement_after_block_id` 与结构化 `rule` 作为模型输出的定位/渲染指令；替换和新增文本分别由 `replacement_markdown` 与 `new_block_markdown` 唯一确定。
- 保留 `cluster_indices`（绑定后为 `cluster_ids`）及行为断言、风险、验证等审计元数据。cluster 仍只表示问题归因，不参与位置或替换文本校验。
- 每个 edit 的影响范围是 replace 的 target 或 add 的 parent。两个影响范围相同、或一方是另一方祖先/后代时拒绝；同级不相交 block 可同时变更。
- locked block 不可替换或作为新增 parent；guarded/evolvable/experimental 的现有流程保持不变。

### 2.3 Renderer 与兼容性

- renderer 仅按 parent Skill hash、SkillMap hash 和重新解析出的标题 block 字节范围执行替换/新增，逆序应用不相交变更，重建 v3 map，并以 unified diff 回放验证。
- 新契约使用新 schema/policy/render-policy 版本；已落盘的 v1 EditPlan 和 v2 SkillMap 仍由旧 renderer 只读渲染，不迁移、不重写。
- v1 计划不能与 v3 map 混用；对本次 `raw-response.txt` 生成的 v1 proposed plan，须在新契约下重新生成，而不是试图自动转换。

## 3. 非目标

- 不实现自由文本行级 patch、列表 item 级 patch、标题外插入点或自动合并。
- 不允许一个 edit 覆盖多个不相邻 block，也不允许 renderer 猜测替换顺序。
- 不改变 cluster 与 edit 的归因关系、候选审批、materialize、评测、真实模型/DSH/Docker/数据库调用或依赖。
- 不修改历史候选、历史 EditPlan、`raw-response.txt` 或现有错误的渲染预览。

## 4. 设计约束

- 所有模型输入、计划、替换文本和 Markdown 均视为不可信；保留 NUL、机械 patch、敏感文本、私有路径与凭据的拒绝边界。
- 校验器只执行必要边界：目标/parent/after 存在且关系正确，locked 保护，replacement/new fragment 的标题边界，祖先-后代影响范围不重叠，以及 patch 回放一致。它不推断规则语义、不自动修复 Markdown、不重排 edit，也不引入列表项级定位。
- 替换模型以 section 为原子性换取定位精度与确定性：需要调整一个 list item 时，模型必须输出所在标题 section 的完整替换内容。
- 不执行全量测试、真实模型、DSH、Docker、数据库或 benchmark；只做针对性静态/单元验证。

## 6. 验收标准

1. 一个含 `#`、`##`、`###` 标题的 SkillMap v3 生成稳定的 `b1`、`b1.2`、`b1.2.4` 路径；序列化 map 仅含 block ID、标题、层级与权限。
2. 无可编辑一级标题、未知 block、错误 parent/after 关系、交叉影响范围和 replacement/new fragment 越出标题边界均被拒绝。
3. 目标/parent 的任一祖先或后代为 locked 时，不能生成或渲染 edit。
4. 每个新模型 edit 只能是一个存在、非 locked block 的 `replace_block`，或一个存在、非 locked parent 下的 `add_block`；旧操作、anchor 与 rule 定位字段被拒绝。
5. 修改 `## Error Recovery` 中某条 list item 的模型输出必须替换整个 `## Error Recovery` block，且保留模型给出的其他该 section 内容。
6. 模型可在 `b1` 下新增一个二级标题，或在 `b1.2` 下新增一个三级标题；不得新增一级标题。祖先/后代 edit 的组合被拒绝；两个不相交的同级 section edit 可确定渲染，且 diff 回放字节一致。
7. 历史 v1 Plan + v2 Map 仍可经明确的旧版 renderer 读取；v1/v3 混配 fail closed。
8. 仅运行相关单元测试、Ruff、mypy 与 `git diff --check`。

## 8. 边界

- **始终：**保留 source/hash 绑定、locked 保护、敏感文本拒绝、不可重叠渲染和历史审计产物。
- **先询问：**本规格批准、实施计划批准、真实模型调用、child materialize、评测、依赖变更与推送。
- **绝不：**把 locked 后代隐藏在可编辑父 block 中；自动转换历史计划；通过行级或列表项 patch 绕开 section 原子性；泄露评测或凭据数据。

## 9. 已确认决定

- 替换文本保留标题行，模型可以修改目标 block 的标题文字，但不能把内容提升为同级或更高层标题。
- 一级标题前的 front matter/文本不可编辑，不创建人工根 block。
