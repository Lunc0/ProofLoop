# 规格：Smoke 仅按通过数 Gate

> **阶段：**24 · **版本：**v0.22 · **状态：**已完成
>
> **前置阶段：**[阶段 16：Smoke 3/5 Gate](16-v0.14-smoke-three-of-five-gate.md)

## 目标

Smoke 完整得到五条 evaluation 后，仅以 `pass` 数量决定 Evolution 准入：`pass >= 3` 即写入 v2 gate。

## 范围与约束

1. `wrong_result`、timeout 映射的 `runner_error`、`runner_invalid` 与 `evaluator_invalid` 不再额外拒绝 gate。
2. 少于五条 evaluation 的早停或基础设施中断仍不得写 gate。
3. run status、结果证据、v2 receipt 格式、候选 binding、Evolution/Final 和 custody 边界不变；不重写历史 receipt。
4. 不运行 Docker、DSH、模型、真实 Smoke/Evolution 或 Final。

## 验收标准

1. 三个 `pass` 加任意两个非通过 evaluation 时，写入记录 `passed_case_count=3` 的 v2 gate。
2. 两个 `pass` 或不足五条 evaluation 时不写 gate。
3. 定向 pytest、Ruff、mypy 与 `git diff --check` 通过。

## 边界

- **始终：**保留原始 run status；gate 不得伪造或绕过五条 evaluation 的完整性要求。
- **先询问：**真实评测、custody/ACL 变更或推送。
- **绝不：**向优化输入泄露 case、GT、Gold、session 或凭据。
