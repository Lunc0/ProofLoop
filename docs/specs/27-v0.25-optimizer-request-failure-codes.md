# 规格：Optimizer Request Failure Codes

> **阶段：**27 · **版本：**v0.25 · **状态：**已完成

## 目标

让 optimizer advice 和 EditPlan 的 receipt 能安全地区分一次模型请求为何失败，避免所有失败都只显示为 `request_failed`。

## 范围

- 为 timeout、网络错误、HTTP 4xx、HTTP 5xx、其他 HTTP 状态、provider 响应格式无效、provider 输出超限和意外客户端异常定义固定的非敏感 error code。
- advice 与 EditPlan 复用同一组分类；既有 `missing_api_key` 与 `invalid_response` 保持含义不变。
- 更新 receipt 合同、客户端、两个服务、定向测试和操作文档。

## 非目标

- 不保存异常消息、URL、HTTP body、模型原文、prompt、题目、session、凭据或绝对路径。
- 不改变 optimizer 调用次数、超时、重试、gate、评分、候选 materialization 或 CLI 输出。
- 不对已有 receipt 做迁移或重写。

## 约束

- receipt 只能存固定枚举值；未知异常统一为 `unexpected_error`。
- HTTP 仅保留状态类别，不能存具体 status code。
- 旧 `request_failed` receipt 必须仍可读取。

## 验收标准

1. timeout、网络、HTTP 4xx/5xx、无效 provider 响应和输出超限均映射到对应固定 code。
2. advice 与 EditPlan 的 `model_failed` receipt 记录相同分类，且不含原始异常内容。
3. 旧 `request_failed` receipt 通过现有 Pydantic 验证。
4. 定向 pytest、Ruff、Mypy 与 `git diff --check` 通过；不执行真实模型、DSH、Docker 或 benchmark。

## 开放问题

无。v0.25 不记录具体 HTTP 状态，以维持最小披露。
