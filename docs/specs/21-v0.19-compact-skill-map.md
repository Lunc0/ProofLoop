# 规格：紧凑 SkillMap 与短编辑锚点

> **阶段：**21 · **版本：**v0.19 · **状态：**已完成
>
> **前置阶段：**[阶段 20：候选内置 SkillMap](20-v0.18-candidate-owned-skill-map.md)
>
> **实施计划：**[阶段 21 v0.19 实施计划](../plans/21-v0.19-compact-skill-map.md)

## 1. 目标

将候选 `SKILL.md` 的 Map 从高冗余审计结构改为给 LLM 和 renderer 使用的紧凑编辑索引。Map 不再为每一个块保存内容
SHA-256、长 hash ID 或完整祖先标题路径；它只保留可作为 renderer target/anchor 的段落与列表，并以短 ID 定位。

## 2. 范围与合同

`skill-map-v2` 的每个 block 仅包含：`id`（`b01` 起的顺序短 ID）、当前 section 标题、行区间、`paragraph` 或 `list`
类型、layer 与 permission。Map 不保存 Skill SHA-256、逐块内容 hash、frontmatter、heading、table 或 fenced code。

LLM 在 cluster 的 `block_ids`、以及 edit 的 `target_block_ids` 或 `placement_after_block_id` 中只返回 `bNN`。本地服务仍从
本次父 Skill 的确定性 Map 查找短 ID，并由 renderer 将其映射为精确文本区间。EditPlan 继续保留既有的父 candidate/Skill
SHA-256 与 Map SHA-256 作为**计划级**绑定；短 ID 只在该精确父版本内有效。

candidate store 不在 Map 内保存任何 hash。verify 从 `SKILL.md` 重建 v2 canonical Map 并逐字节比较 persisted map；这是本 MVP
唯一的 Map 一致性检查。

## 3. 兼容性与迁移

新 candidate 一律写 v2 Map。旧 v1 Map 不被 v2 verify 接受；新增显式 `candidate rebuild-skill-map <candidate-id>` 命令，
从现有 `SKILL.md` 原子替换为 v2 Map。普通读取、评测、optimizer 与 materialization 不隐式迁移。

已有 v1 EditPlan 仍属于其原始 parent/Map 合同；本阶段不承诺它们可用 v2 renderer materialize。新的计划一律生成 v2 short ID。

## 4. 非目标

- 不改变标题分类白名单、permission/layer 语义、EditPlan 操作种类或 SQL 评测行为。
- 不新增签名、远端认证、NLP 库、第三方 Markdown parser 或完整 Skill 重写。
- 不运行模型、DSH、Docker、数据库或任何 benchmark。

## 5. 技术栈、结构与代码风格

继续使用 Python 3.11+、Pydantic、标准库正则、pytest、ruff 与 mypy。改动位于 `optimizer/edit_plan_contracts.py`、
`optimizer/skill_map.py`、candidate store/CLI、renderer 与相关测试。严格 Pydantic 合同、`snake_case`、确定性排序和
UTF-8/symlink 路径边界保持不变。

```python
block_id = f"b{editable_index:02d}"
```

## 6. 验证与验收标准

1. 7.7 KB 的 DBHub Skill 产生显著小于旧 17 KB Map 的 v2 artifact，且不含 `content_sha256`、64 位 digest 或 `block-` ID。
2. 相同 Skill bytes 产生字节稳定的 v2 Map；paragraph/list 顺序确定短 ID，非目标 Markdown 结构不出现在 Map 中。
3. LLM 计划可以引用 `bNN`；bind 与 renderer 将它定位回正确的父文本区间；未知、locked 或跨版本 target 仍被拒绝。
4. candidate init/import 生成 v2 Map，verify 通过重建比较检测缺失、篡改或旧 v1 Map；显式 rebuild 可迁移一个指定候选。
5. 只运行无模型、无网络、无 Docker 的定向 pytest、ruff、mypy 与 `git diff --check`。

## 7. 边界

- **始终：**从本地 `SKILL.md` 确定性建图；只让本地 renderer 使用短 ID；保留计划级父 Skill hash 绑定。
- **先询问：**改变 permission 分类、让模型直接输出行号、恢复逐块 hash、或兼容 materialize 既有 v1 EditPlan。
- **绝不：**把短 ID 当作跨 candidate 版本的稳定标识；让 LLM 提供补丁、绝对路径、哈希或原始评测数据。

## 8. 开放问题

无。本阶段按上述 v2 MVP 合同实施。
