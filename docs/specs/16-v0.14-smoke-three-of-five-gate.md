# 规格：Smoke 3/5 Gate

> **阶段：**16 · **版本：**v0.14 · **状态：**已完成
>
> **前置阶段：**[阶段 15：Smoke 固定配额与 4/5 Gate](15-v0.13-smoke-quota-and-gate.md)

## 1. 目标

将当前 Smoke→Evolution gate 的最低通过数从 4/5 调整为 3/5。新写入的 gate 仍为 v2 receipt，并明确记录
`minimum_passed_case_count=3`。Smoke 固定 Simple 3、Moderate 2、Challenging 0，以及 Evolution 的 15 题三层配额不变。

## 2. 范围

1. 完整执行五题、通过数为 3、4 或 5，且没有 `runner_invalid` 或 `evaluator_invalid` 时，写入 v2 gate。
2. 2 题及以下、早停或基础设施无效时不得写 gate。
3. 4/5 的 run status 仍为 `task_failure`；3/5 也同样保留 `task_failure`，gate 仅表示 Evolution 准入资格。
4. 已有 v2、门槛为 4 的 receipt 不修改但继续有效；历史 v1 receipt 与历史 Smoke manifest 仍只可审计，不得放行或运行。
5. 更新当前操作文档、合成测试及阶段索引；不改写阶段 15 的历史规格、计划或实现记录。

## 3. 非目标与约束

- 不改变 Smoke manifest 配额、Evolution/Final、runner、评分、candidate binding、optimizer 合同或 CLI 参数。
- 不伪造 receipt，不重写 custody 中的历史记录，不记录 case、题目、GT、Gold、session 或凭据。
- 不运行真实 DSH、模型、Docker、数据库或评测集；只运行合成定向测试与静态检查。

## 4. 验收标准

1. 新 v2 receipt 的最小通过数为 3；3/5、4/5、5/5 可放行 Evolution，2/5 不可放行。
2. `runner_invalid`、`evaluator_invalid` 或不足五个 evaluation 不可放行。
3. 既有 v2 4/5 receipt 仍能被安全读取和承认；v1 receipt 仍不承认。
4. 定向 pytest、Ruff、mypy 与 `git diff --check` 通过。

## 5. 边界

- **始终：**从已验证 evaluation 计算通过数，并保留真实 run status。
- **先询问：**运行任何真实评测、改变 custody/ACL 或推送远端。
- **绝不：**让 Final/held-out 进入优化输入，或通过伪造 gate 绕过评测。
