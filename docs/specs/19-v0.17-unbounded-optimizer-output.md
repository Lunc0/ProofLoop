# 规格：Optimizer 无应用层输出上限

> **阶段：**19 · **版本：**v0.17 · **状态：**已完成

## 目标

允许 Evolution optimizer 的单次 DeepSeek 请求不再由本项目设置或校验输出 token 上限，以避免结构化 EditPlan 因本地 `max_tokens` 截断而成为无效 JSON。

## 范围

- `OptimizerConfig.max_output_tokens` 支持省略；省略时不向 provider 发送 `max_tokens`，也不执行依赖该值的响应字节上限检查。
- 显式提供该字段时，继续按指定值传给 provider 并执行相应本地响应大小检查。
- 更新配置、DeepSeek request 构造与定向测试。

## 非目标

- 不改变 provider 自身的输出、配额、超时或计费限制。
- 不重跑已有 DSH、Docker、Evolution 或 Final；不自动重试 optimizer 请求。
- 不改变输入大小限制、密钥处理、轨迹投影、EditPlan 合同、candidate materialization 或 Git 推送行为。

## 约束

- 不设应用层上限会增加单次成本、延迟和本地审计文件大小；远端请求仍须用户明确授权。
- 原始模型返回不可信，仍须通过 JSON、schema、evidence、Skill block 和 target-contract 校验后才可 materialize。
- 不得持久化凭据、GT、Gold、原始 session 或 custody 内容。

## 验收标准

1. 缺失或为 `null` 时，DeepSeek request 不含 `max_tokens`，且不执行旧 token 推导的响应大小检查。
2. 提供正整数时，仍发送 `max_tokens` 并保留相应响应大小检查。
3. 配置、DeepSeek client、advice 与 EditPlan 定向测试通过，且不调用真实 provider。

## 开放问题

无。provider 侧限制不在本阶段控制范围内。
