# 规格：Benchmark DSH 禁用 Web Search 配置 Patch

> **阶段：**12 · **版本：**v0.10 · **状态：**已完成
>
> **前置阶段：**[阶段 11：Evolution 后 LLM 优化建议 MVP](11-v0.9-evolution-llm-optimization-advice.md)

## 1. 目标

为 SQL benchmark 提供一个受版本控制的 DSH profile patch，使通过该 manifest 启动的 `headless` DSH
不向模型注册 `web_search` 或 `web_fetch`。这消除通过 DSH 官方 web 工具搜索 LiveSQLBench、Hugging Face
或其他公开 benchmark 资料的路径，避免该外部信息污染评测结果。

## 2. 已采用的前提

1. 只使用 DSH `tool-web` 的配置覆盖：`search: false`、`fetch: false`；不改用户全局
   `DSH_HOME` profile，也不编辑 DSH 安装目录。
2. patch 必须位于 manifest workspace 内，由现有 `dsh.profile_patch` 解析并作为 `--patch` 传入 DSH。
3. 本阶段不启动 DSH、模型、Docker、数据库或 benchmark。
4. 禁用 `tool-web` 不构成通用网络或文件读取隔离；`pwsh`、本机可读 benchmark 文件和 OS/网络边界留待独立
   安全阶段处理。

## 3. 范围

- 在仓库中增加可复用的无 web DSH patch。
- 使选定的 SQL benchmark DSH manifest 引用该 patch。
- 更新配置文档，说明该 patch 的作用、适用范围和限制。
- 增加不启动外部进程的测试，确认 manifest 解析与最终 DSH argv 含有该 patch。

## 4. 非目标

- 不实现 OS ACL、独立账户、容器/VM、网络出口白名单或通用 shell 限制。
- 不把 `environment.tools` 误作 DSH runtime 工具 allowlist。
- 不修改 DSH 全局 profile、用户 settings、provider route 或凭据。
- 不重跑或修改任何历史 benchmark 结果。

## 5. 约束

- patch、manifest 和文档不得包含 API key、token、密码、GT、held-out case ID、prompt、逐题结果或 custody
  路径。
- 保持现有 `DshRunner` 的 argv array 与 `shell=False` 合同。
- 真实 Final 的私有 DSH manifest 不在 Git 中；受信任 evaluator 必须在其受控 manifest workspace 中复制并引用
  同一 patch 内容。

## 6. 验收标准

1. 选定 manifest 的 `environment.dsh.profile_patch` 可被 loader 解析为其 workspace 内的现有文件。
2. patch 将 `tool-web` 的 `search` 和 `fetch` 都设为 `false`。
3. mock 的 DSH invocation 在 `--profile` 后包含该 patch，且不依赖真实 DSH 或模型。
4. 文档明确：该变更只删除 DSH web 工具，不等于网络隔离或 held-out 文件访问控制。
5. 定向单元测试通过；不执行 Docker、DSH、模型或完整测评。

## 7. 已确认的实施入口与后续事项

`examples/sql-agent/experiment.dsh.yaml` 是本阶段的仓库内默认入口，并将直接引用无 web patch。私有
Final manifest 不应提交到仓库；受信任 evaluator 应在其受控 workspace 中复制同一 patch 内容并显式引用它。

将“无 web”提升为所有 benchmark run 的 runner 强制策略仍是后续独立阶段，不包含在本阶段。
