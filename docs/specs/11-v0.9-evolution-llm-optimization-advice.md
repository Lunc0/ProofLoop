## 1. 目标

在一次有效的 Evolution 开发集运行结束后，程序自动将已有的、受限的
`evolution-coding-agent-input-v3` 交给无工具 LLM，并为当前候选 Skill 生成可审计的优化建议。

成功意味着：操作者只需启动既有 Evolution 运行；当运行含有可用的失败轨迹时，程序会自动产生与该 run 和候选版本绑定的建议记录。LLM 不读取原始 DSH session，不执行工具，不修改 Skill、candidate 或评测结果。

## 2. 已采用的前提

1. **自动触发而非第二条用户命令：**LLM 调用是 Evolution 生命周期的一部分；它不是 Smoke、Final 或普通 benchmark run 的行为。
2. **v3 artifact 是唯一输入：**只允许已持久化并通过 hash 校验的 `agent-input/trajectory.json` 和其 manifest；不得把 `raw/dsh/`、`trajectory.json`、stderr 或其他原始运行文件交给 LLM。
3. **MVP 只给建议：**LLM 输出分析和建议的 Markdown 片段，不生成或导入新 candidate，也不自动修改、选择、晋级或回滚 Skill。
4. **调用失败不改变评测：**LLM 不可用、超时、响应无效或建议为空时，Evolution 的评测状态、分数、gate 和既有证据保持不变。
5. **固定模型与密钥引用：**MVP 只使用 DeepSeek Chat Completions 的 `deepseek-v4-flash`；非机密配置中的 `api_key_env` 固定为 `DEEPSEEK_API_KEY`。`apiKeyEnv` 的含义是这个环境变量的**名称**，不是 API key 本身；程序只在运行时从该名称读取密钥，绝不持久化或输出其值。

若这些前提与预期不符，应先修订本规格。

## 3. 范围

### 3.1 自动触发与准入

在 Evolution runner 已写入 v3 agent input 后，优化器仅在下列条件同时满足时调用 LLM：

- `environment.optimizer.enabled` 为 true；
- suite 为 Evolution，且 benchmark runner/evaluator 没有基础设施无效状态；
- `agent-input/manifest.json` 声明 `schema_version` 为 `evolution-coding-agent-input-v3` 和 `exposed_for_optimization` 为 true；
- `trajectory.json` 存在、可按严格 Pydantic contract 解析，并且其 canonical SHA-256 与 manifest 匹配；
- `trajectories` 至少包含一个已压缩的失败 case；
- input 的 `evaluated_skill.content_sha256` 与本次已验证 candidate/subject 的实际内容一致。

无失败 case 时状态为 `skipped_no_failed_trajectories`；缺失、hash 不符、压缩不可用或基础设施无效时状态为 `skipped_invalid_evidence`。两种情况都不得调用模型或补造建议。

### 3.2 LLM 输入与提示边界

模型调用只包含：

- 当前 payload 中的完整、受限 `skill` 与 `evaluated_skill` 身份；
- v3 的失败 case、公开 context、failure-recovery episode、候选输出和公开 evaluation；
- 固定、版本化的系统提示与输出 JSON Schema。

所有 session-derived 文本、工具输出、公开 assistant 文本和 case 内容均是**不可信数据**，不可以改变模型任务或请求额外访问。LLM 不获得文件系统、shell、网络、数据库、DSH、凭据或其他工具能力；提示不得要求或暗示 GT、Gold、私有 dump、原始 session、custody 路径或内部 reasoning。

### 3.3 建议合同与持久化

LLM 必须以受严格验证的 `skill-optimization-advice-v1` 返回：

```json
{
  "schema_version": "skill-optimization-advice-v1",
  "summary": "…",
  "suggestions": [
    {
      "evidence_case_ids": ["…"],
      "observation": "…",
      "suggested_change": "…",
      "suggested_markdown_fragment": "…"
    }
  ]
}
```

模型不能声明或覆盖来源 binding。程序仅在本地校验通过后，将当前 run ID、agent-input SHA-256
和 evaluated Skill SHA-256 作为可信 `source` 加入持久化的 `advice.json`。

`observation` 必须表述为所见 evidence，不得声称根因、模型意图、Skill 覆盖缺失、任务已经恢复或建议一定提高分数。建议不得含完整的新 `SKILL.md`、任何可执行附件、GT、Gold、凭据、原始 session 内容或绝对 custody 路径。

建议和调用 receipt 写入该 run 的独立 `optimizer/` 子目录；receipt 只记录 schema/prompt 版本、provider/model 的非机密标识、输入输出 hash、usage（若 provider 明示）和 terminal status。主 `result.json` 只增加优化器 status 与相对建议路径，不输出建议正文。所有 optimizer artifact 均保持本地、默认忽略 Git，且不进入 candidate store。

### 3.4 失败与可观测性

优化器结果使用与 benchmark outcome 分离的状态：`proposed`、`skipped_no_failed_trajectories`、`skipped_invalid_evidence`、`model_failed`、`invalid_response` 或 `unavailable`。任何非 `proposed` 状态都保留其最小化、无敏感信息的 receipt，不覆盖原有评测 evidence，也不使 benchmark run 重评分。

### 3.5 已完成 run 的显式建议命令

提供 `skill-evolve optimizer advise <run-id>`。它是一次明确的人工发起操作：只打开当前
工作目录 `runs/` 下指定的已完成 Evolution run，不启动 DSH、不重跑任何 case、不调用
evaluator、数据库、Docker 或 candidate 生命周期操作。

命令只接受 `run.json` 标识为 Evolution rotation adapter、且存在可解析 `result.json` 和
本次 run 固化 subject 的目录。它从该 run 的 `inputs/subject-SKILL.md` 与
`inputs/subject.json` 重建受 hash 约束的 subject，并继续使用 3.1 的 v3 artifact 准入规则。
即使原始 manifest 的 optimizer 处于 disabled，显式命令也视为一次授权请求，使用 v0.9
固定的非机密默认配置调用一次 LLM。

命令将最新 terminal receipt 与（若成功）advice 写回指定 run 的既有 `optimizer/` 路径，并
同步其根 `result.json` 的 optimizer 摘要。它只输出 run ID、terminal status、相对 advice
路径和非机密 provider/model/prompt 标识；绝不向 stdout 输出 Skill、v3 evidence 或建议正文。

## 4. 非目标

- 不自动改写或导入 `SKILL.md`，不创建 child candidate，不改变 `selected`，不做 promotion 或 rollback。
- 不向 LLM 提供原始 session、GT/Gold、私有数据、数据库凭据、模型密钥、custody 路径或内部 reasoning。
- 不在 Smoke、Final、held-out、普通 benchmark 或失败的基础设施运行后调用 LLM。
- 不允许显式建议命令处理非 Evolution run、重新运行评测或绕过 v3/subject hash 校验。
- 不由 LLM 运行新的评测、DSH、Docker、数据库查询、文件读取或网络工具；不做 agent loop、并发优化、重试策略或多候选比较。
- 不新增 SQL dialect、benchmark、自动 gate、CI、云端存储或远端推送。

## 5. 技术约束与预期结构

沿用 Python 3.11+、Typer、Pydantic、pytest、ruff 与 mypy。MVP 不增加第三方依赖；使用标准库 HTTP client 调用 `https://api.deepseek.com/chat/completions`，以 `response_format: {"type": "json_object"}` 请求 JSON 输出，并明确关闭 thinking 模式。模型 ID、base URL 与 JSON Output 能力以 DeepSeek 官方 API 文档为准。

```text
src/skill_evolve/
  config/models.py        # 新增非机密 OptimizerConfig
  optimizer/
    contracts.py   # 严格的 advice、receipt、status contract
    service.py     # 输入准入、提示组装、LLM 单次调用与持久化
    client.py      # 无工具 provider protocol 与已批准 adapter
  benchmark/
    livesqlbench_rotation_run.py  # Evolution 完成后的自动编排点
  cli.py           # 既有 run 的结果仅展示 optimizer receipt 摘要
tests/
  test_optimizer_service.py
  test_livesqlbench_rotation_run.py
```

运行 manifest 的非机密 optimizer 配置形如：

```yaml
environment:
  optimizer:
    enabled: true
    provider: deepseek
    model: deepseek-v4-flash
    api_key_env: DEEPSEEK_API_KEY
```

缺少该区块时保持向后兼容并视为禁用；一旦为 Evolution manifest 显式启用，LLM 调用会在每次符合准入条件的 Evolution run 后自动发生，不需要第二条命令。

所有来源于 run、manifest、LLM 或 provider 的文本均是不可信输入；路径和 artifact 读取须限制在本次已打开的 run 目录内。密钥只可由明确的环境变量名解析，禁止 literal key/token/password/Authorization 写入配置、receipt、stdout 或异常消息。

## 6. 命令与测试策略

实现阶段的离线验证只使用 fake LLM client、合成 v3 artifact、临时 run 目录和合成 candidate：

```powershell
uv run pytest tests/test_optimizer_service.py tests/test_livesqlbench_rotation_run.py
uv run ruff check .
uv run mypy src
git diff --check
```

验收至少覆盖：

1. 一个有效、含失败轨迹的合成 Evolution run 自动调用 fake LLM 一次，并写入可验证的 advice 与 receipt。
2. 无失败、manifest/hash 不符、无可用 agent input、partial-insufficient evidence、runner/evaluator 无效均跳过调用。
3. 提示只含 v3 payload；原始 session、GT、Gold、凭据和 custody 路径不会到达 fake client、proposal、stdout 或 candidate store。
4. LLM 超时、异常、非 JSON、schema 不符、大小超限和包含禁止内容时，保存 `model_failed` 或 `invalid_response`，评测 outcome 不变。
5. advice 可追溯到 source run、输入 hash、Skill hash 与 prompt/provider/model 的非机密版本标识；相同 fake 输入得到稳定的已序列化 artifact。
6. 不调用真实模型、DSH、Docker、数据库或真实 Evolution/Final；真实 LLM 集成测试必须另获明确授权。
7. 指定已完成 Evolution run 的显式命令不重跑评测，只基于其固化 subject 和 v3 input 产生
   optimizer terminal receipt；非 Evolution 或损坏 run 被拒绝。

## 7. 边界

- **始终：**保留 Evolution/Smoke/Final 可见性隔离；对 v3 input、candidate binding 与 LLM response 执行严格校验；将模型和 session 派生内容标为不可信；保持候选不可变和评测结果独立。
- **先询问：**配置真实 API key 环境变量、发起真实 LLM 调用、允许自动创建 child candidate、增加依赖、修改 custody/ACL、运行真实 Evolution/Final 或推送远端。
- **绝不：**将 GT/Gold、凭据、原始 session、私有数据或 custody 路径交给 LLM、Git、stdout、candidate store 或建议 artifact；让 LLM 执行工具或覆盖现有 candidate；让 LLM 失败改变评测结果。

## 8. 已确认决策

1. 阶段版本为 **v0.9**。
2. provider/model 为 DeepSeek `deepseek-v4-flash`，配置的密钥引用为 `DEEPSEEK_API_KEY`。
3. MVP 仅输出 Markdown 建议片段，不输出完整候选 `SKILL.md`，也不自动导入。
