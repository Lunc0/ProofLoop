# 实施计划：Codex Coding Agent 原子 Skill 编辑路径

> **阶段：**29 · **版本：**v0.27 · **状态：**已完成

## 关联规格

[v0.27 规格](../specs/29-v0.27-codex-coding-agent-optimizer-path.md)。

## 总体方案

新增 `skill_evolve.optimizer.coding_agent` 包，形成与 DeepSeek advice/EditPlan 完全并行的路径。`agent-edit` 负责受控 workspace、Codex CLI 调用、正式输出绑定与 replay；`agent-materialize` 只读取 validated artifacts，生成一个 full 与 N 个 singleton draft siblings。现有 Evolution cycle、DeepSeek contracts 和历史 artifacts 不进入新控制流。

启动器要求 Codex CLI >= 0.138.0。本机离线 probe 为 0.153.1。调用使用 `--ignore-user-config` 继续从 `CODEX_HOME` 读取认证，并通过重复 `-c key=value` 参数注入 strict custom permission profile；不传 `--sandbox`。固定关闭 approval、Web Search、apps、multi-agent、memories、hooks 和 login shell，workspace root 只读、`output` 子目录可写、sandbox command network disabled。

## 任务与依赖

### Task 1：原子声明、绑定与 replay 合同

**工作：**新增 strict/frozen Pydantic contracts、固定状态/error code、字节安全 heading range 解析，以及从 agent declaration 到 bound edits、full/singleton bytes 和 patch 的确定性转换。

**验收：**

- 只接受 1–3 个 `replace_block`，每个 edit 引用闭集 evidence ID。
- 系统本地生成 edit ID、parent/map/evidence hash、半开字节区间和 before/replacement hash。
- locked/guarded、重复/父子重叠、空变更、结构无效和 full-output 不等价均 fail closed。

**验证：**`uv run pytest tests/test_coding_agent_contracts.py tests/test_atomic_skill_replay.py`

**依赖：**无。

**文件：**`optimizer/coding_agent/contracts.py`、`optimizer/coding_agent/replay.py`、对应测试。

### Task 2：受控 workspace 与 Codex CLI launcher

**工作：**创建专用 workspace layout、输入 manifest/hash、permission profile argv、版本 probe、prompt stdin、超时进程控制和 input post-hash。subprocess 通过 injectable runner 测试，不调用真实 Codex。

**验收：**

- argv 使用 `shell=False`、ephemeral、ignore config/rules、strict config、never approval 和 disabled web/tools。
- profile 只读 workspace 并只写 `output`，不传 `--sandbox`，CLI 版本不足时拒绝。
- 只采信两个普通 output 文件；输入变化或路径逃逸拒绝。

**验证：**`uv run pytest tests/test_coding_agent_workspace.py tests/test_coding_agent_launcher.py`

**依赖：**Task 1 的输入/输出合同。

**文件：**`optimizer/coding_agent/workspace.py`、`optimizer/coding_agent/launcher.py`、对应测试。

### Checkpoint A

- 核心 contracts、replay 与 launcher 定向测试通过。
- inspect argv 确认没有 `--sandbox`、`--yolo`、仓库/custody/candidate 路径或凭据值。

### Task 3：agent-edit service 与 artifacts

**工作：**复用当前 Evolution subject/evidence projection，发布独立 invocation/raw/bound/receipt artifacts；所有 terminal path 使用固定非敏感 code，并在 validated 前不写 candidate。

**验收：**

- 现有 run/subject/evidence 绑定不满足时不启动 agent。
- raw output 与 bound artifacts 分开；stdout 成功声明不影响状态。
- 任一 launcher/binding/replay 失败产生稳定 receipt，且不覆盖旧 optimizer namespace。

**验证：**`uv run pytest tests/test_coding_agent_service.py tests/test_optimizer_cli.py`

**依赖：**Tasks 1–2。

**文件：**`optimizer/coding_agent/service.py`、`optimizer/coding_agent/prompt.py`、`cli.py`、对应测试。

### Task 4：full/singleton candidate 物化与 provenance

**工作：**新增独立 coding-agent provenance union/字段，扩展 candidate import 验证，并从 validated bound artifacts 创建 full 与 singleton draft siblings。

**验收：**

- full 应用全部 edits，singleton 各自只应用一个 edit，全部绑定同一 parent/run。
- provenance 区分 role/edit ID，绑定 atomic edits、patch、SkillMap、evidence 与 policy hash。
- 不自动 select、benchmark、promote、retire 或改变 Evolution 下一代 parent。

**验证：**`uv run pytest tests/test_coding_agent_materialization.py tests/test_candidate_store.py`

**依赖：**Tasks 1、3。

**文件：**`candidate/contracts.py`、`candidate/service.py`、`optimizer/coding_agent/materialization.py`、对应测试。

### Checkpoint B

- 既有 optimizer/Evolution 定向回归测试通过。

## 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| permission profile 的 CLI config 语义随版本变化 | 可能意外放宽权限 | 最低版本 0.138.0、`--strict-config`、固定 argv 单测、能力不足 fail closed |
| Windows path/junction/hardlink 绕过 | input 或私有根可被访问/覆盖 | 独立根、realpath/重叠/reparse 检查、输出只接收普通文件、post-hash |
| Unicode 字符使字符 offset 与字节 offset 混淆 | replay 绑定错误 | 新路径始终以 UTF-8 bytes 计算半开范围和 hash |
| 一次生成多个 candidate 时中途失败 | 留下部分 siblings | 写入前完成所有名称、bytes、patch 与 provenance 预检；receipt 明确列出实际创建结果 |
| 新旧 optimizer artifacts 或 provenance 混淆 | 历史兼容性与审计错误 | 独立 namespace、schema、service、result key 和 provenance 类型 |
| agent 声明与真实 Skill 不一致 | 未声明改动进入 candidate | full bytes equality 是发布 bound artifacts 的硬门禁 |

## 非并行项

contracts → launcher → service → materialization → CLI/design 存在直接依赖，本阶段顺序实施。共享仓库当前还有用户未提交的 `OptimizerConfig.timeout_ms` 修改；实现不得覆盖或提交该变化。
