# 实施计划：Evolution 后 LLM 优化建议 MVP

> **阶段：**11 · **版本：**v0.9 · **状态：**已完成
>
> **依据规格：**[Evolution 后 LLM 优化建议 MVP](../specs/11-v0.9-evolution-llm-optimization-advice.md)
>
> **实现记录：**[v0.9 实现记录](../design/11-v0.9-evolution-llm-optimization-advice.md)

## 1. 实施目标与边界

在已启用的 Evolution run 中，v3 agent input 落盘并完成原有评测后，自动调用一次无工具的 DeepSeek `deepseek-v4-flash`，写入只含 Markdown 优化建议片段的本地 artifact。该调用不是新的 CLI 命令，也不会运行在 Smoke、Final、held-out 或普通 benchmark 路径中。

本计划只实现建议闭环：**v3 evidence → DeepSeek 单次 JSON 输出 → 严格验证的本地 advice/receipt**。不生成完整 `SKILL.md`，不导入 candidate，不改变 `selected`、评分、gate 或 comparison key。模型、session 和 provider 输出均为不可信数据。

DeepSeek 采用其 OpenAI-compatible Chat Completions endpoint `https://api.deepseek.com/chat/completions`、model ID `deepseek-v4-flash` 和 JSON Output；请求显式设定 `thinking.type: disabled`，不请求或持久化 reasoning。密钥只在运行时通过 `DEEPSEEK_API_KEY` 读取。

## 2. 架构决策

1. **以 manifest 显式启用自动化。**新增非机密 `environment.optimizer`；既有 manifest 缺少该区块时保持禁用，避免历史或非 Evolution 运行产生意外 API 成本。配置启用后不需要额外的操作者命令。
2. **配置与评测模型分离。**`OptimizerConfig` 记录 DeepSeek provider/model、`api_key_env`、timeout、输出上限和 prompt version；它不更改 DSH 的 `ModelConfig`、DSH provider route 或 Evolution comparison key。receipt 单独记录其非机密 provenance。
3. **只信任 v3 input 的完整性，不信任其文本。**服务严格验证 `agent-input/manifest.json`、canonical SHA-256、Pydantic v3 contract 和 subject/Skill hash；通过验证的 payload 仍作为带明确边界的不可信数据嵌入固定提示。
4. **建议是独立 artifact。**在 `runs/<run-id>/optimizer/` 写入 `advice.json`、`advice.md` 与 `receipt.json`；根 `result.json` 仅保存 optimizer status、相对路径和无密钥 provenance。candidate store 不读取也不保存这些文件。
5. **失败降级而非重评分。**LLM 未配置、网络/API 失败或返回无效时，优化器写入最小 receipt 并返回非成功状态；随后仍按原逻辑写入 benchmark result，评测 outcome 不变。
6. **标准库 HTTP、可替换 client。**定义同步 `OptimizerClient` Protocol。生产 `DeepSeekChatClient` 使用 `urllib.request`；测试注入 fake client，禁止任何单元或集成测试发起网络请求。

## 3. 改动范围

| 模块 | 改动 |
| --- | --- |
| `config/models.py`、config/fingerprint tests | `OptimizerConfig` 与 manifest 的非机密、严格校验；缺省禁用。 |
| `optimizer/contracts.py` | advice、receipt、terminal status、provider request/response 的严格 Pydantic contract。 |
| `optimizer/service.py` | v3 artifact 准入、提示组装、输出校验、受限 artifact 写入。 |
| `optimizer/deepseek.py` | 单次 DeepSeek JSON Chat Completion 调用、环境变量读取、无密钥错误归一化。 |
| `benchmark/contracts.py`、rotation adapter/run | 传递 optimizer 配置/客户端，并在 Evolution 完成后编排建议服务。 |
| `tests/test_optimizer_*.py`、现有 rotation/config tests | fake client 与合成 run 的安全、失败和集成回归。 |
| `docs/configuration.md` | 非机密 optimizer 配置和 `DEEPSEEK_API_KEY` 的说明；不写入真实值。 |

## 4. 有序任务

### 任务 1：定义非机密 optimizer 配置与结果合同

新增严格、冻结的 `OptimizerConfig`、`OptimizationAdvice`、`OptimizerReceipt` 和 terminal status enum。`api_key_env` 仅接受合法环境变量名；禁止出现 literal key/token/password/Authorization 值。为旧 manifest 提供 disabled 默认值。

**验收：**

- [x] 启用配置只能选择 `deepseek` / `deepseek-v4-flash` / `DEEPSEEK_API_KEY`，并有受限 timeout 和输出上限。
- [x] advice 只接受本地 source binding、摘要、evidence case ID、观察、建议与 Markdown 片段；拒绝完整 Skill、NUL、超限文本和额外字段。
- [x] 旧 manifest 在不触发模型调用的情况下仍可解析。

**验证：**`uv run pytest tests/test_config_and_fingerprint.py tests/test_optimizer_contracts.py`

**依赖：**无。**预计文件：**`config/models.py`、`optimizer/contracts.py`、`tests/test_config_and_fingerprint.py`、`tests/test_optimizer_contracts.py`。

### 任务 2：实现 v3 准入、提示与本地 advice 持久化

实现纯服务层：限定在当前 `RunDirectory` 内读取 v3 manifest/payload，校验 digest、schema、失败轨迹和 active Skill binding；对通过的输入构建固定、版本化提示，并把 v3 JSON 作为 untrusted data。服务验证模型返回 JSON，产生 `advice.json`、渲染后的 `advice.md` 与最小 `receipt.json`。

**验收：**

- [x] manifest 缺失、quality unavailable、hash 不符、零失败轨迹、基础设施无效或 Skill hash 不符都会跳过，并不调用 client。
- [x] prompt 不包含 raw session、GT、Gold、凭据、custody 路径或工具指令；建议 artifact 不写入 candidate store。
- [x] 相同 fake input 与 response 生成稳定的 advice/receipt bytes；错误只写无敏感的 terminal status。

**验证：**`uv run pytest tests/test_optimizer_service.py`

**依赖：**任务 1。**预计文件：**`optimizer/service.py`、`registry/store.py`（若需要受限读取辅助）、`tests/test_optimizer_service.py`、`optimizer/contracts.py`。

### 任务 3：实现无工具 DeepSeek 单次 client

实现 `OptimizerClient` Protocol 和 `DeepSeekChatClient`。客户端只发送一次非流式 `POST /chat/completions`，指定 `deepseek-v4-flash`、`response_format: {"type": "json_object"}`、`thinking.type: "disabled"` 和输出上限。它从 `DEEPSEEK_API_KEY` 解析 Bearer 凭据，但不在请求、异常、receipt 或 stdout 中暴露其值。

**验收：**

- [x] 缺失/空环境变量返回 `unavailable`，不发网络请求。
- [x] URL、method、非机密 header、JSON body 和响应 content 的提取经 stub HTTP transport 验证。
- [x] 非 2xx、超时、无 choices/content、非 JSON 或 payload 超限映射为不含密钥的失败。

**验证：**`uv run pytest tests/test_optimizer_deepseek.py`

**依赖：**任务 1。**预计文件：**`optimizer/client.py`、`optimizer/deepseek.py`、`tests/test_optimizer_deepseek.py`。

### 检查点 A：离线优化器闭环

- [x] 任务 1–3 的定向 pytest 通过，且测试只使用 fake client/transport、合成 v3 input 和临时目录。
- [x] 审阅生成 artifact，确认其中没有 raw session、GT、Gold、凭据或完整 `SKILL.md`。
- [x] 不进行真实 DeepSeek 调用。

### 任务 4：接入 Evolution 的自动编排与结果 receipt

扩展 benchmark adapter/run 调用链以传递已解析的 optimizer 配置和 client。在 Evolution 已写入 v3 agent input、计算运行 status 后调用服务，再将 receipt 摘要加入根 `result.json`；Smoke、Final 和非 Evolution 路径不导入该服务。Benchmark result 即使优化器失败也保持原 status、指标、score/cost 和 comparison key。

**验收：**

- [x] 启用配置且有效失败 evidence 时，Evolution 自动调用 fake client 恰好一次并写 `optimizer/` artifact。
- [x] 通过、无 evidence、超时/runner invalid、evaluator invalid 与未启用配置不会调用 client，并有正确 skip 状态。
- [x] `result.json` 只含 status、相对 artifact 路径、prompt/provider/model 的非机密标识；既有 Smoke/Final 行为和 gate 不变。

**验证：**`uv run pytest tests/test_livesqlbench_rotation_run.py tests/test_optimizer_service.py`

**依赖：**任务 2–3。**预计文件：**`benchmark/contracts.py`、`benchmark/livesqlbench_rotation_adapter.py`、`benchmark/livesqlbench_rotation_run.py`、`tests/test_livesqlbench_rotation_run.py`、`tests/test_optimizer_integration.py`。

### 任务 5：补齐本机配置说明与全量离线验证

**验收：**

- [x] 配置说明没有任何密钥值、GT、Gold 或 session 样例。
- [x] 所有新增与既有测试通过，静态检查通过，Git diff 没有空白错误。

**验证：**

### 任务 6：增加指定 run 的显式建议 CLI

新增 `optimizer advise <run-id>` 子命令。它打开本地已完成的 Evolution run，验证 adapter、
result、materialised subject 和 v3 evidence；显式命令以固定非机密 optimizer 默认配置调用
既有服务，不再执行 benchmark。调用后的 receipt 摘要写回该 run 的 `result.json`，CLI 仅输出
安全摘要。

**验收：**

- [x] 有效 Evolution run 可由 fake 服务路径产生一次 advice，且 CLI 不创建第二个 run 或调用
  DSH/fixture。
- [x] 非 Evolution、缺少/篡改 subject、无 result 或无效 v3 evidence 返回 usage error，且不调用
  provider。
- [x] 成功与失败结果均只输出安全摘要；不会打印 Skill、prompt、evidence 或建议正文。

**验证：**`uv run pytest tests/test_optimizer_cli.py tests/test_optimizer_service.py`

**依赖：**任务 1–5。**预计文件：**`cli.py`、`optimizer/service.py`、
`tests/test_optimizer_cli.py`、`docs/configuration.md`。

## 5. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| session 文本包含 prompt injection | LLM 建议偏离优化任务 | 只输入 v3、无工具、固定系统提示、显式 untrusted 标签；建议永不自动执行。 |
| provider/API 或模型行为变化 | 调用或 JSON 解析失败 | 固定 model ID 和 prompt version；将 API 响应归一化为 receipt；真实调用另获授权。 |
| 自动调用产生成本 | Evolution run 成本上升 | manifest 显式启用、每 run 至多一次、设置 timeout/输出上限，并记录 provider usage。 |
| 失败 evidence 不足 | 无根据建议 | 准入失败即 skip，不让模型访问原始 session 或补猜。 |
| 优化器影响评测可比性 | 分数/归因被污染 | optimizer status 与 benchmark outcome 分离，不触碰 comparison key、gate、score 或 candidate。 |

## 6. 实施检查点与交付

任务 1–3 必须顺序完成，任务 4 依赖其全部合同；任务 5 在代码路径稳定后完成。任务 6 复用
已经稳定的服务与 artifact 合同。没有适合与共享 contract 并行修改的任务。

实现完成后，才更新 `docs/design/11-v0.9-evolution-llm-optimization-advice.md` 描述实际 API contract、artifact 结构、验证结果及未执行的真实调用。真实 DeepSeek 请求、真实 Evolution、候选导入与推送不属于本计划的默认验证，均需新的明确授权。
