# 实施计划：Benchmark DSH 禁用 Web Search 配置 Patch

> **阶段：**12 · **版本：**v0.10 · **状态：**已完成
>
> **依据规格：**[Benchmark DSH 禁用 Web Search 配置 Patch](../specs/12-v0.10-dsh-no-web-profile-patch.md)

## 1. 实现方式

新增与 `experiment.dsh.yaml` 同一 workspace 的 DSH patch。它只覆盖 `tool-web` 的 `search` 与 `fetch`
开关为 `false`；manifest 通过现有 `environment.dsh.profile_patch` 指向该文件。现有 loader 已将该路径限制在
manifest workspace 内，`DshRunner` 已将已解析路径作为 `--patch` 放在 `--profile` 之后，因此不需要改动
runner、provider route 或全局 DSH 配置。

## 2. 任务

### 任务 1：添加并绑定无 Web patch

- [x] 新增 `examples/sql-agent/dsh-no-web.patch.yml`。
- [x] 在 `examples/sql-agent/experiment.dsh.yaml` 的 `environment.dsh` 中引用它。
- 验收：patch 仅含 `tool-web` 的 `search: false` 与 `fetch: false`，不含凭据或外部路径。

### 任务 2：覆盖 manifest 到 DSH argv 的无进程测试

- [x] 在现有 DSH runner 测试中加载示例 manifest，检查已解析 patch 内容，并检查构造的 DSH argv 引用该文件。
- 验收：测试不启动 DSH、模型、Docker 或数据库。

### 任务 3：说明适用范围和限制

- [x] 在 `docs/configuration.md` 记录示例入口已关闭 DSH web 工具。
- [x] 明确实际 Final 的私有 manifest 必须自行引用同一 patch；该 patch 不限制 `pwsh` 联网或本机可读文件。

## 3. 检查点与验证

完成任务 1–3 后执行：

```powershell
uv run pytest tests/test_dsh_runner.py
uv run ruff check examples/sql-agent tests/test_dsh_runner.py
```

检查 `git diff --check`。不执行 DSH、模型、Docker、数据库或 benchmark。

## 4. 风险

| 风险 | 缓解 |
| --- | --- |
| 私有 Final manifest 未继承仓库示例 | 文档要求 evaluator 在其受控 workspace 显式复制并引用 patch。 |
| 被误解为完整联网隔离 | 文档明确仅移除 DSH `web_search` / `web_fetch`。 |
| 未来 argv 覆盖次序改变 | 定向测试断言 manifest patch 已进入构造的 DSH argv。 |
