# 实施计划：紧凑 SkillMap 与短编辑锚点

> **阶段：**21 · **版本：**v0.19 · **状态：**已完成
>
> **依据规格：**[阶段 21 v0.19 规格](../specs/21-v0.19-compact-skill-map.md)

## 1. 实施顺序

1. 修改 Map/Block Pydantic 合同与 parser：只输出 paragraph/list，生成 `bNN`，删除逐块和根 hash 字段。
2. 更新 EditPlan 的 block ID 校验、Map 绑定与 renderer，以短 ID 解析精确区间。
3. 让 candidate store 通过重建的 canonical Map 验证文件，并增加显式 rebuild CLI。
4. 改写 Map、candidate、EditPlan/renderer 测试；迁移现有 DBHub candidate；执行定向检查。
5. 写入 design record 与索引。

## 2. 风险与检查点

| 风险 | 缓解 |
| --- | --- |
| 短 ID 在不同版本重复 | 只在 exact parent/plan binding 内使用；parent Skill hash 继续在 EditPlan source 中校验。 |
| v1 Map 导致现有 candidate verify 失败 | 只提供显式 rebuild，不做隐式迁移；实现后仅迁移当前 DBHub candidate。 |
| 精简后 renderer 丢失文本位置 | Map 保留起止行；添加 insertion/replacement 回归测试。 |
