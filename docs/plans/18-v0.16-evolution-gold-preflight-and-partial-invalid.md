# 实施计划：Evolution Gold Preflight 与部分无效 Case 隔离

> **阶段：**18 · **版本：**v0.16 · **状态：**已完成
>
> **依据规格：**[阶段 18 v0.16 规格](../specs/18-next-evolution-gold-preflight-and-partial-invalid.md)

## 1. 实施目标

在 rolling Evolution 的 DSH 前执行 trusted Gold preflight；将不可执行的 Gold case 排除在 DSH、评测指标和 optimizer projection 之外。若仍有有效失败轨迹，cycle 继续调用既有 advice、EditPlan 与 materialization；部分结果保持不可作为完整可比分数。Smoke、Final 和零有效 case 继续 fail-closed。

## 2. 架构决策与依赖图

```text
frozen Evolution suite
  -> trusted Gold preflight (custody receipt, aggregate only)
  -> eligible cases -> DSH + Soft-EX
  -> valid failed trajectories -> optimizer
  -> partial receipt / cycle continuation
```

1. **Preflight 只对 Evolution 生效。** Smoke 与 Final 保持既有无效即停止的行为，避免放宽 gate 或 held-out 语义。
2. **Gold 仅在 trusted process 内执行。** preflight 复用 `LiveSQLBenchFixture` 与只读执行器；持久化和公共投影只包含安全 aggregate / 分类，不包含 SQL、原始错误、case ID 或 custody 路径。
3. **`partial_evaluator_invalid` 是非评分状态。** 它表示至少一个 case 有效、至少一个 case 因 evaluator 无效被排除；comparison key、完整成本与 macro score 均不可用。optimizer 的唯一资格条件是存在已投影的有效失败轨迹。
4. **运行期防御仍保留。** 即使 preflight 后在 Soft-EX 阶段收到单 case `evaluator_invalid`，该 case 也不进入投影，其余有效 case 继续；fixture 启动/runner 级错误继续为全局无效。
5. **Runner error 按 case 隔离。** Evolution 排除任意单 case runner error 而不中断剩余 case；只将明确 timeout 且 `partial_actionable` 的轨迹投影给 optimizer。存在有效评测 case 或可行动 timeout 轨迹时产生 `partial_runner_error`；仅完全没有这两类证据时为 `runner_invalid`。
6. **receipt 放在 rotation custody。** 使用原子写入、不可覆盖、可校验的最小 receipt；run/cycle stdout 仅显示 aggregate，不能反推 Gold 或 case 身份。

## 3. 有序任务与检查点

### 任务 1：扩展部分无效合同与 Gold preflight 证据

**文件：**`benchmark/livesqlbench_rotation_run.py`、`benchmark/livesqlbench_rotation.py`、`tests/test_livesqlbench_rotation_run.py`

**内容：**定义 `partial_evaluator_invalid`、安全 aggregate、custody receipt 与单数据库 fixture preflight；根据 Gold 执行结果构建 eligible suite view，不改写 manifest。

**验收：**无效 Gold case 零 DSH；零 eligible case 保持 `evaluator_invalid`；receipt 不含 Gold、原始错误或 case ID。

**验证：**`uv run pytest tests/test_livesqlbench_rotation_run.py`

### 任务 2：完成部分结果、投影与 optimizer 资格路径

**文件：**`benchmark/livesqlbench_rotation_run.py`、`optimizer/service.py`、相关测试

**内容：**只压缩有效失败 case；部分状态清空 formal metrics/comparison key；optimizer 接受部分状态但只有非空、完整性通过的 projection 才可调用 provider。

**验收：**无效 case 不出现于 agent input；有效失败仍出现；没有有效失败则 optimizer 不调用。

**验证：**`uv run pytest tests/test_livesqlbench_rotation_run.py tests/test_optimizer_service.py`

- [x] 所有投影负向断言均不含私有评测字段。

**文件：**`evolution/contracts.py`、`evolution/service.py`、`tests/test_evolution_cycle.py`

**验收：**partial + valid failure 调用 advice/plan/materialize；partial + no valid failure 不调用任何 provider；全局 `evaluator_invalid` 和 `runner_invalid` 仍停止。

**验收：**可行动 timeout 调用优化器；不可压缩或非 timeout runner error 被丢弃而不进入优化器；有效失败仍继续，Smoke/Final 行为不变。

**验证：**`uv run pytest tests/test_livesqlbench_rotation_run.py tests/test_evolution_cycle.py tests/test_optimizer_service.py`

## 4. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| Gold preflight 泄露私有材料 | 高 | 仅 custody receipt + aggregate；测试对 stdout/run/agent input 负向断言。 |
| 部分结果被误读为评分 | 高 | 新 status；metrics、cost、comparison key 显式不可用。 |
| preflight 与运行期结果不一致 | 中 | 保留 Soft-EX 运行期单 case 防御，且同一 fixture/evaluator 版本进入 receipt fingerprint。 |
| 无效 case 仍调用模型 | 高 | eligible case view 在 DSH 前形成；fake runner 调用计数测试。 |
| 测试触发真实服务 | 高 | monkeypatch fixture / DSH / optimizer；默认只运行定向测试和静态检查。 |
