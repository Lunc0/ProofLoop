# 阶段 05 实施计划：本地 SQL Skill 候选版本库与受控演进

> **阶段：**05 · **版本：**v0.5 · **状态：**已完成
> **依据规格：**[阶段 05 规格](../specs/05-v0.5-local-skill-evolution.md)

## 实施目标

在不连接真实 DSH 或模型的前提下，实现被 Git 忽略的本地单文件 SQL Skill 候选库，并把一份已验证候选的身份和 SHA-256 安全地连接至普通 workflow 与 LiveSQLBench 的每题隔离执行。LiveSQLBench 的 PostgreSQL fixture、只读查询能力、私有 GT Soft-EX 评分，以及 timeout/非零退出时的脱敏 session log 必须保持原有行为。

## 实施方案与边界

- 新增 `candidate` 包：Pydantic 严格契约定义 metadata/catalog；store 负责 root 限制、常规文件检查、内容哈希、原子写入和谱系校验；service 仅编排 init/import/list/show/select/verify。
- candidate ID 仅是受限的 `skill-id/candidate-name`；候选目录只接受一个 UTF-8、非空且有大小上限的 `SKILL.md`。没有动态 import、执行或外部附件通道。
- CLI 只经 candidate ID 解析已验证候选；失败统一转换为退出码 64，且发生在 DSH/fixture 初始化之前。
- 对普通 workflow 和 benchmark 运行分别使用显式 `ResolvedCandidate` 合约，将 candidate ID 和 hash 加入环境 fingerprint、run metadata 和受控 copied inputs；候选正文不拼入命令行。
- LiveSQLBench 每个 case 建立新 workspace，只写入 `candidate/SKILL.md`、公开 prompt/schema/context 和既有只读 capability；固定任务文件指示 DSH 先读取该文件。GT 继续仅由 adapter 持有和本地评分。
- DBHub 上游 baseline 的 canonical URL、具体 commit、文件 hash、来源仓库和 MIT 许可存入 external metadata；`NOTICE.md` 保存在候选库，但不进入 agent workspace。实现不下载、安装或启动 DBHub。

## 有序任务与检查点

1. 建立 candidate 类型、受限 ID/文本/来源校验，以及 root-confined 原子 store；为 init/import/verify/lineage 写单元测试。
   - 验收：hash、catalog/metadata 一致性、重复与路径逃逸、父版本和环检测均可确定性验证。
2. 增加 candidate service 和 CLI，并将 `.local/skill-evolve/` 忽略。
   - 验收：candidate 命令只输出公开元数据，并以 64 拒绝坏输入且不遗留部分状态。
3. 将已验证 candidate 作为显式运行输入，写入 snapshot、普通 run evidence 和 copied input；保持旧 manifest candidate 行为。
   - 验收：candidate ID/hash 改变必定改变 fingerprint；无 candidate 的旧命令和测试不变。

### 检查点：store 与普通 workflow

- 运行 candidate 单元/CLI/workflow 测试、Ruff 和 Mypy。
- 核查外部 candidate 的 `NOTICE.md` 不会成为普通 workspace 输入。

4. 给 `benchmark run` 添加 `--candidate`，并在 adapter/runner 边界传递已验证候选。
   - 验收：未知或损坏 ID 在启动 fixture/DSH 前失败；每题独立执行保留 candidate ID/hash evidence。
5. 扩展 DSH workspace 构造和固定任务文本，并增加 stub DSH 注入/隔离/脱敏回归测试。
   - 验收：DSH 只得到 `candidate/SKILL.md`、公开文件和既有只读 capability；Gold、GT、凭据及未脱敏 log 不出现于其输入或公开 artifacts。

### 检查点：端到端候选运行

- 运行完整 `pytest`，覆盖 LiveSQLBench PostgreSQL fixture、Soft-EX、timeout 与非零退出 session 捕获。
- 运行 `uv run ruff check .`、`uv run mypy src`、`git diff --check`。

6. 根据实际代码和验证结果写 `docs/design/v0.5-local-skill-evolution.md`，并更新两个目录索引为“已完成”。
   - 验收：设计文档只陈述完成且验证过的 A/B/C 行为，明确 D/E 未实现。

## 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| catalog/metadata 或本地文件被篡改 | 错误候选进入 DSH | 每次 resolve 重新算 hash，并交叉校验 metadata/catalog/谱系。 |
| 非可信路径、symlink 或非文本输入 | workspace/本机越界或执行入口 | resolve root、拒绝 symlink/目录/二进制/超限文件，只以 bytes 复制。 |
| candidate 注入改变现有 runner 行为 | LiveSQLBench 评分或日志回归 | 可选合约保持旧调用路径，复用既有 fixture/只读服务，加入 stub 和回归测试。 |
| private GT 泄漏 | 评测完整性受损 | adapter 私有持有 GT；单独测试禁止字符串进入 workspace、job、输出和 report。 |
| 上游 baseline 漂移 | 无法审计来源 | external metadata 需要 canonical URL、commit、repo、MIT 与 bytes hash；不接受移动分支引用。 |
