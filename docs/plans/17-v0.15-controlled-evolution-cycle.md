# 实施计划：受控自动进化循环

> **阶段：**17 · **版本：**v0.15 · **状态：**已完成
>
> **依据规格：**[阶段 17 v0.15 规格](../specs/17-next-controlled-evolution-cycle.md)

## 1. 实施目标

新增显式的 `skill-evolve evolution cycle`，使一个既有 local candidate 在用户给定的 1 至 100 代内自动完成 rotation reserve 检查、基线第 1 代的 Smoke 豁免、后续代 Smoke 3/5 gate、Evolution、一次 advice、一次 EditPlan 和确定性 child materialization。它复用现有 custody、runner、optimizer 与 candidate 服务，不经 shell 拼接、不新增后台任务，也不运行 Final/held-out。

## 2. 架构决策与依赖图

```text
CLI request
  -> EvolutionCycleRequest validation
  -> CandidateService.verify + manifest load
  -> reserve ensure/load
  -> [baseline gen 1: Evolution] | [child gen N: Smoke -> gate -> Evolution]
  -> advice -> plan -> materialize
  -> CycleReceipt safe summary
```

1. **新 service 直接复用 trusted Python APIs。** cycle 从 `load_manifest`、`create_rotation_manifest`、`load_rotation_suite`、`run_rotation_dsh_suite` 和三段 optimizer service 获取结构化结果，不重新解析 CLI stdout，也不启动嵌套进程。
2. **Smoke 豁免只在 runner 内显式、内部地传递。** `run_rotation_dsh_suite` 新增默认拒绝的 `allow_ungated_evolution` 参数；只有 cycle 已验证“起始 candidate 无父代且 generation=1”时传入 true。现有 `benchmark run` 和所有普通调用继续要求有效 Smoke receipt。
3. **optimizer 配置从 DSH manifest 继承。** cycle 先拒绝 `enabled: true`；Evolution 使用原样的 disabled config，advice/plan 使用同一对象仅把 `enabled` 置为 true，因此每个 Evolution 的 provider 请求只有这两次。
4. **receipt 是公开、安全的 terminal summary。** 它只含 candidate/run ID、manifest hash、gate/terminal status 与停止原因；不复制完整 Skill、计划、patch、case、session、GT/Gold、custody 路径或凭据。
5. **名称先验验证。** 按 `<prefix>-<generation:03d>` 产生 child name，并在 Evolution/provider 调用前使用 existing candidate store 验证 name 合法且尚不存在；冲突 fail closed。

## 4. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| baseline gate 例外扩散到普通评测 | 高 | 默认 false 的参数；仅 service 经 lineage + generation 双重验证传 true；回归普通拒绝路径。 |
| disabled Evolution 残留 optimizer receipt 与后续结果混淆 | 中 | cycle 用单独、明确的 result 摘要覆盖同名 terminal summary，并在 receipt 标记编排阶段。 |
| 多代 child 名称冲突或部分写入 | 高 | provider 前预检查；materialization 继续复用原子 candidate store；失败即停。 |
| 测试意外调用 DSH/模型 | 高 | dependencies 注入 fake runner/client；不设置真实凭据或 custody；只跑定向 tests。 |
| stdout/evidence 泄露私有评测信息 | 高 | 只序列化显式白名单 receipt；保持现有 optimizer/trajectory 安全合同和负向断言。 |
