# 实施计划：候选内置 SkillMap

> **阶段：**20 · **版本：**v0.18 · **状态：**已完成
>
> **依据规格：**[阶段 20 v0.18 规格](../specs/20-v0.18-candidate-owned-skill-map.md) ·
> **实现记录：**[阶段 20 v0.18 实现记录](../design/20-v0.18-candidate-owned-skill-map.md)

## 1. 实施方式

MVP 将复用现有 `skill_evolve.optimizer.skill_map.build_skill_map()` 与 `SkillMap` 合同，不移动模块、不修改 metadata，
也不改变 optimizer 从 run subject 即时建图的行为。candidate store 在写入候选时同时生成并原子写入 `skill-map.json`；读取
时验证其 JSON/schema 与 `skill_sha256`。历史候选使用显式 CLI 回填，绝不在普通读取、评测或 optimizer 中隐式改写。

## 2. 有序任务

### 任务 1：候选存储写入和读取 Map

修改 `LocalCandidateStore`：从已验证的 Skill bytes 生成 canonical `skill-map.json`；将其纳入 staging 原子写入、候选目录
允许文件集合与读取校验。Map 缺失、损坏、symlink、非 UTF-8 或 Skill hash 不一致时 fail closed。

**验收：**新建本地/外部/child candidate 都含 Map；篡改或删除 Map 的候选不能 verify。

**涉及文件：**`src/skill_evolve/candidate/store.py`、`tests/test_candidate_store.py`。

### 任务 2：显式历史回填服务与 CLI

增加只针对一个 candidate ID 的 Map 回填方法和 `candidate backfill-skill-map` 命令。它先验证旧候选，拒绝覆盖已有 Map，
并在成功后只新增一个本地生成的 Map。

**验收：**旧 candidate 可显式补齐 Map；普通 `verify` 不会写文件；已存在 Map 时回填报错且不覆盖。

**涉及文件：**`src/skill_evolve/candidate/store.py`、`src/skill_evolve/candidate/service.py`、`src/skill_evolve/cli.py`、
`tests/test_candidate_store.py`、`tests/test_candidate_cli.py`。

### 检查点：候选生命周期

运行候选存储与 CLI 定向测试；不调用 provider、DSH、Docker、数据库或 benchmark。

### 任务 3：Map 与 EditPlan 回归

补充/调整测试，证明 Map 仍字节稳定，模型返回无效 EditPlan 时已存在的 candidate Map 不受 run artifact 发布影响，并确认
既有 optimizer 的即时 Map 行为不变。

**验收：**candidate Map 与成功/失败 EditPlan artifact 互不覆盖；既有 EditPlan 服务测试通过。

**涉及文件：**`tests/test_skill_map.py`、`tests/test_edit_plan_service.py`，必要时 `tests/test_optimizer_cli.py`。

### 任务 4：文档收口

实施后将规格状态改为已完成，更新三个文档索引，并新增 design record，如实记录 MVP 未做的 metadata binding 与 optimizer 输入改造。

**验收：**spec → plan → implementation → design 链路和索引完整；不将计划表述成已实现。

**涉及文件：**`docs/specs/`、`docs/plans/`、`docs/design/` 的对应文件与 README。

## 3. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 严格要求 Map 会让存量 candidate 立即不可读 | 先提供显式回填命令；实现后仅对用户指定的候选执行，不进行批量自动写入。 |
| `skill-map.json` 作为新允许文件弱化原有附件拒绝测试 | 仅允许精确文件名；仍拒绝所有其他附件和 symlink。 |
| candidate store 依赖 optimizer Map 模块 | 这是 MVP 的有意复用；后续再提取共享模块，避免扩大本阶段。 |
| Map 规则更改造成旧 Map 过时 | policy version 已在 Map 内；本阶段遇到不支持版本直接拒绝，不自动升级。 |
