# 实施计划：EditPlan 渲染、机械校验与不可变 Child Skill

> **阶段：**14 · **版本：**v0.12 · **状态：**已完成
>
> **依据规格：**[阶段 14 v0.12 规格](../specs/14-v0.12-edit-plan-render-child-candidate.md) ·
> **实现记录：**[阶段 14 v0.12 实现记录](../design/14-v0.12-edit-plan-render-child-candidate.md)

## 1. 实施目标

为已完成 Evolution run 中的 `skill-edit-plan-v1` 增加显式
`skill-evolve optimizer materialize <run-id> --candidate-name <child-name>` 路径。该路径以确定性 renderer
生成 `SKILL.md` 单文件 patch，完成精简的 parent/target/diff 校验，并通过既有本地候选库原子创建一个带完整来源信息的
draft child。

同时，阶段 13 不再为新的 guarded edit 写出 `requires_guarded_approval`：guarded 保持为结构定位风险标签，新的
plan 统一为 `proposed`；仅在读取历史 v0.11 artifact 时兼容并归一该旧值。

## 2. 架构决策

1. **保留 permission，删除审批状态。** `SkillPermission` 和 `skill_map.py` 的 guarded heading mapping 不变；
   移除新计划写出 `requires_guarded_approval` 的 service 分支、状态合同和测试断言。materialization reader 对历史值
   单独归一，避免把兼容性重新暴露给新写路径。
2. **renderer 无模型且模板化。** 新模块只接受已绑定的 `SemanticEdit`、parent bytes 与 `skill-edit-render-policy-v1`；
   使用标准库生成 Markdown 片段与 unified diff。无法与 target/anchor 对齐的 operation 返回受控失败，绝不整篇重排。
3. **校验保持最小闭环。** 只验证 run/parent/plan binding、target 存在且非 locked、non-empty diff 可应用回 parent、
   locked block 不变、每项 edit 恰好一次，以及敏感文本拒绝；不重做阶段 13 的 evidence/contract/全量 map 审计。
4. **candidate provenance 放在 metadata。** 为 `CandidateOrigin` 增加 `optimizer`，并以可选、冻结的 optimizer provenance
   子结构保存 plan/patch/policy/parent hash。旧 metadata 仍可读取，candidate 目录仍仅含 `SKILL.md` 和 `metadata.json`。
5. **materialization evidence 与 candidate 写入分开原子化。** run 内仅发布 `optimizer/materialization/rendered.patch` 和
   `receipt.json`；candidate 仍通过 `CandidateService.import_candidate` 创建。任一前置失败都不得写 child。

### 任务 3：实现确定性 renderer 与最小 diff 校验

**涉及文件：**

- `src/skill_evolve/optimizer/edit_plan_renderer.py`（新增）
- `tests/test_edit_plan_renderer.py`（新增）

**实施内容：**

1. 为四类 rule definition 和八种 semantic operation 定义有限的插入、替换、合并、删除与重排模板。
2. 保留未命中 parent bytes 的行尾与内容，使用标准库 `difflib` 生成单文件 `SKILL.md` unified diff。
3. 校验 diff 非空、可应用到 exact parent、locked block 不变、每个 edit 只对应一次 hunk，并拒绝敏感/非法 child 文本。

**验收：**相同输入产生逐字节稳定的 child 与 patch；不支持的 target 形状返回 `render_failed`；额外 hunk、no-op、locked
变更或不可回放 diff 均失败。

**验证：**

```powershell

```

**依赖：**任务 2。
**规模：**S。

## 4. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 语义 edit 不能无损映射为文本 | 明确 renderer template 与 `render_failed`，不回退为自由重写。 |
| 删除状态导致旧 artifact 读失败 | 新写路径只用两种状态；materialization reader 在唯一边界归一历史值。 |
| child 元数据扩展破坏历史候选 | provenance 使用可选严格子结构；保留 v1 schema 与旧字段。 |
| patch 与 child 内容不一致 | 创建 child 前 round-trip 应用 patch 并比较 exact bytes。 |
| 不相关的完整评测被触发 | 所有测试使用合成 artifact、fake store，无 provider/DSH/Docker/DB 调用。 |
