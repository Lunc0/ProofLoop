# 实施计划：EditPlan 位置语义与问题-变更分层

> **阶段：**22 · **版本：**v0.20 · **状态：**已完成
>
> **依据规格：**[阶段 22 v0.20 规格](../specs/22-next-edit-plan-location-semantics.md)
>
> **实现记录：**[阶段 22 v0.20 实现记录](../design/22-v0.20-edit-plan-location-semantics.md)

## 1. 实施方式

保持 `DefectCluster` 为问题和证据单位，保持 `ModelSemanticEdit.cluster_indices` 的既有多对多关联；不新增持久化类型、自动合并或编辑顺序。仅使新模型响应按 operation 使用唯一且明确的文本落点：新增规则只使用 insertion anchor，改写/删除/合并规则只使用 target。

历史 bound `SkillEditPlan` 与 renderer 不变，继续接受旧 `add_rule` 的 target fallback；严格组合只施加于生成阶段解析的 `ModelSemanticEdit`。

## 2. 文件与任务

### 任务 1：为模型响应增加 operation 位置组合校验

修改 `src/skill_evolve/optimizer/edit_plan_contracts.py` 的 `ModelSemanticEdit` 后置校验。

- `add_rule`：拒绝 target；要求一个 `placement_after_block_id`。
- 改写/删除/优先级/泛化操作：要求一个 target；拒绝 placement。
- `merge_rules`：要求至少两个 target；拒绝 placement。
- `reorder_workflow`：要求一个 target、拒绝 placement；以其 `WorkflowRule` 文本替换整个 target block。

**验收：**错误组合在 `ModelEditPlan.model_validate*` 时失败，且错误信息点出 operation 与落点字段。

### 任务 2：将提示词改为问题-变更两层说明

修改 `src/skill_evolve/optimizer/edit_plan_service.py` 的 trusted system prompt。

- 明确 cluster 是问题/跨 case 证据单位，edit 是不可重叠的最终文本变更。
- 明确共同落点的兼容 cluster 合入一个 edit；同一 cluster 可引用多个不重叠 edit。
- 明确每种 operation 的 target/placement 二选一规则。

**验收：**fake client 捕获的 prompt 包含上述三类约束，且不放宽现有 evidence、permission、traceability 或不重叠要求。

### 任务 3：补充定向回归测试

修改 `tests/test_edit_plan_contracts.py` 与 `tests/test_edit_plan_service.py`。

- 覆盖 `add_rule` 的正确 anchor-only 形状及 target/both/missing 的拒绝。
- 覆盖改写类操作的 target-only 形状及 anchor/both/missing 的拒绝。
- 覆盖一个 edit 关联多个 cluster，以及同一 cluster 出现在多个互不重叠 edit 中的绑定成功。
- 保留现有 renderer 用例，证明历史 bound `add_rule` 的 target fallback 仍可渲染。

**验收：**新测试不依赖 provider、DSH、Docker、数据库或真实 benchmark。

## 3. 检查点与验证

先运行定向测试；通过后再运行静态检查。不得运行完整 pytest、真实模型、DSH、Docker、数据库或评测。

## 4. 风险与处理

| 风险 | 处理 |
| --- | --- |
| 当前工作树已有 optimizer 改动 | 不还原、不覆盖；只在其上作小范围 patch，并在交付时分列本阶段文件。 |
| 已持久化计划依赖 `add_rule` target fallback | 只收紧 `ModelSemanticEdit`；不收紧 `SemanticEdit` 或 renderer。 |
| 多问题无法合成为一个确定的同块变更 | 保持 fail closed；不引入隐式顺序或自动合并。 |
| 模型仍违反新规则 | 保留 raw response 审计；在 schema 层尽早拒绝，不尝试修改模型输出。 |

## 5. 非目标

不改 CLI、candidate lifecycle、materialization evidence、SkillMap、目标合同、provider 配置或版本；不推送、不创建 candidate，也不执行任何真实运行。
