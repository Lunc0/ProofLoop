# 实施计划：Smoke 固定 Simple/Moderate 配额与 4/5 Gate

> **阶段：**15 · **版本：**v0.13 · **状态：**已完成
>
> **依据规格：**[阶段 15 规格](../specs/15-v0.13-smoke-quota-and-gate.md)

## 1. 实施目标

将新建 Smoke manifest 固定为 Simple 3、Moderate 2、Challenging 0；将能够放行 Evolution 的 Smoke gate 调整为 5 个 case 中至少 4 个 `passed`。历史 `2/2/1` Smoke manifest 和 v1 gate receipt 保留可审计读取，但不能被当作当前 Smoke 输入或 Evolution 准入证明。

Evolution 仍然每层 5 题、共 15 题，Final、reserve、candidate 和 optimizer 的隔离合同不改变。

## 2. 现状与技术方案

当前 Smoke 配额由三个 `2/2/1` 轮换常量按 `selection_index` 选择，rotation manifest 与 gate receipt 都是 v1。运行器只在五题均为 `passed` 时写 gate，gate 查找会接受任何验证过摘要的 v1 receipt。

实施采用显式版本界线，避免把历史记录误当成新 policy：

1. rotation manifest 支持读取 v1 与 v2。新建 Smoke manifest 写入 v2；v2 Smoke 严格验证固定 `3/2/0`，v1 继续按历史轮换配额验证，供审计读取。Evolution 仍新建 v1 manifest，并保持既有 `5/5/5` 合同。
2. `load_rotation_suite` 在 Smoke 运行入口拒绝 v1 manifest，因此旧 Smoke 不会在 Docker、DSH 或模型前启动。Evolution 的 v1 manifest 不受此限制，因为其配额合同未变。
3. gate receipt 支持严格读取 v1 与 v2。新 receipt 为 v2，并记录 `passed_case_count`、`case_count=5` 和 `minimum_passed_case_count=4`；仅有效 v2 receipt 能通过 Evolution gate 查找。
4. 运行器继续将任一 task case 失败报告为 `task_failure`，不把 4/5 伪装成完整 run 成功；但当完整五题已执行、无 runner/evaluator 无效状态且通过数为 4 或 5 时，额外写入 v2 gate。

## 4. 有序任务与检查点

1. 先将已批准规格固定为 v0.13，并建立本计划及目录索引。
   - 检查点：计划明确 v1 审计兼容、v1 Smoke 运行拒绝和 v2 gate 限制。
2. 修改 rotation manifest 模型与配额选择。
   - 新建 Smoke 写 v2、固定 `3/2/0`；Evolution 继续写 v1；保留 v1 可解析；在运行入口拒绝 v1 Smoke。
   - 检查点：不更改任何既有 custody 文件，也不改变 Evolution `5/5/5`。
3. 修改 gate receipt 和 gate 资格计算。
   - 从已验证 evaluation 计数，只有完整五题且 4 或 5 个 `passed`、无基础设施无效时写 v2 receipt。
   - 检查点：4/5 run 状态仍真实反映为 `task_failure`，仅 gate 资格变化；v1 receipt 永不放行 Evolution。
4. 扩展合成测试与更新操作文档。
   - 检查点：断言不泄露 case 材料，且历史数据仅被读取、不被写回。
5. 执行定向无模型验证、静态检查和 diff 检查；据实写 design record 并更新索引。

## 5. 风险与控制

- **把旧 gate 误认成新 gate：**由 receipt schema v2 和 gate 查询只接受 v2 双重限制。
- **旧 Smoke 被实际启动：**在 `load_rotation_suite` 的 Smoke 分支、任何环境/runner 构造之前 fail closed。
- **将部分失败掩盖为成功：**保留 run status 的原语义；receipt 明确记录通过数和 4/5 门槛。
- **破坏 Evolution 可复现性：**Evolution 使用独立固定 `5/5/5` quota，保留其 v1 加载兼容。
- **意外触发成本或泄露：**仅使用测试中的合成数据；不调用 DSH、Docker、数据库、模型或真实 held-out。
