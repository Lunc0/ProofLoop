# 实施计划：层级 Markdown SkillMap 与整块替换 EditPlan

> **阶段：**23 · **版本：**v0.21 · **状态：**已完成
>
> **规格：**[阶段 23 规格](../specs/23-v0.21-hierarchical-markdown-skill-map.md)

## 1. 实施概述

新路径使用紧凑的标题 SkillMap v3 和 replace/add 两种 edit。标题范围只在 renderer/binder 内存中解析，不进入 map artifact；模型只能按路径替换一个完整 section，或在指定 parent 下新增一个子 section。旧 v1 Plan + v2 Map 维持可读、可渲染的独立路径。

## 2. 架构决定

```text
Markdown Skill
  └─ heading parser ──> compact SkillMap v3 (id/title/level/permission)
                         ├─> model prompt + v2 plan binder
                         └─> v2 renderer (reparse private byte spans)

legacy v1 plan + v2 map ──> legacy renderer ──> legacy provenance policy
```

- 标题 parser 忽略 fenced code 内的伪标题，基于标题层级求 section 范围和祖先关系；范围仅作为内部实现数据。
- v2 edit 的 `operation` 只有 `replace_block`、`add_block`。replace 包含完整同级标题 section；add 指向 parent、可选直接子 `after`，并包含 parent 下一级的完整新 section。
- 绑定器以 block 路径前缀判定祖先/后代影响范围，以 parser 查询判定 locked 祖先/后代；不做 rule 内容、cluster 归因或 Markdown 自动修复推断。
- render 结果携带实际使用的 policy version，materialize 以该版本写 provenance，避免 legacy plan 被标记为 v3。

## 3. 任务

### 任务 1：实现紧凑标题 SkillMap v3 与私有范围解析

**内容：**在现有 parser 旁建立 v3 标题树、稳定路径 ID、权限分类和内部 section-span 查询；对模型 artifact 仅序列化四个约定字段。

**验收：**

- [ ] `#` / `##` / `###` 生成 `b1` / `b1.2` / `b1.2.4`，范围包含正确子树。
- [ ] fenced code 内 `#` 文本不生成 block；没有一级标题的文档不能产生 v3 map。
- [ ] 序列化 map 不含行号、范围、block_type 或 layer。

**验证：**`tests/test_skill_map.py` 的新 v3 正反例。

**依赖：**无。

**文件：**`src/skill_evolve/optimizer/skill_map.py`、`src/skill_evolve/optimizer/edit_plan_contracts.py`、`tests/test_skill_map.py`。

### 任务 2：建立 replace/add v2 Plan 合同与绑定器

**内容：**新增版本化模型/持久化 Plan 合同，替换 prompt、schema 和 `_bind_plan`；保留 cluster-to-edit 归因，删除 v2 新输出的旧 operation、anchor 与结构化 rule 定位字段。

**验收：**

- [ ] replace 仅接受一个非 locked block 与合法完整同级 section。
- [ ] add 只能在非 locked parent 下新增下一级 section，`after` 仅能是该 parent 的直接子 block。
- [ ] 相同或祖先/后代影响范围、未知 ID、locked 祖先/后代、敏感文本均 fail closed；同级不相交 edit 可绑定。

**验证：**合同与 service 单元测试，不调用模型。

**依赖：**任务 1。

**文件：**`src/skill_evolve/optimizer/edit_plan_contracts.py`、`src/skill_evolve/optimizer/edit_plan_service.py`、`tests/test_edit_plan_contracts.py`、`tests/test_edit_plan_service.py`。

### 检查点：map 与计划绑定

- [ ] v3 map 不泄露内部范围资料。
- [ ] v2 model schema/prompt 无旧位置操作。
- [ ] 锁定与嵌套冲突的负例全部通过。

### 任务 3：实现 v2 section renderer 并保留旧版渲染路径

**内容：**为 v2 plan 重新解析 parent Markdown，执行完整 section 替换或 child section 插入，并检查 fragment 标题边界、逆序范围、生成 map 与 unified diff 回放；将 v1 renderer 保持为显式 legacy 路径。

**验收：**

- [ ] 替换 `## Error Recovery` 会整体替换该 section，保留后续同级 section。
- [ ] add 可在指定 parent 下的 `after` 后或末尾插入；不得生成一级标题或越出 parent 边界。
- [ ] legacy v1/v2 artifact 仍可渲染；v1/v3 混配失败，不发生隐式转换。

**验证：**renderer 单测涵盖替换、两种新增位置、标题边界、嵌套冲突和 byte-exact patch 回放。

**依赖：**任务 1、任务 2。

**文件：**`src/skill_evolve/optimizer/edit_plan_renderer.py`、`src/skill_evolve/optimizer/materialization_service.py`、`tests/test_edit_plan_renderer.py`、`tests/test_materialization_service.py`。

### 任务 4：按实际 renderer policy 写入候选 provenance

**内容：**扩展 provenance 的允许版本和 materialize 测试，确保每个 child 候选记录实际执行的 legacy/v3 renderer policy。

**验收：**

- [ ] 新 v2 plan 的 child provenance 记录 v3 policy。
- [ ] legacy v1 plan 的 child provenance 保持其 legacy policy。
- [ ] 不改变 candidate 不可变写入、parent hash 校验或审批边界。

**验证：**candidate store 与 materialization 单测。

## 4. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 标题 parser 把 fenced code 当标题 | 错误 target 或覆盖范围 | 单元测试覆盖 code fence，解析器仅处理 fence 外 ATX 标题。 |
| 通过父 block 替换绕过 locked 子 block | 破坏保护边界 | binder/renderer 都按路径查询祖先与后代 locked 状态。 |
| 旧计划被新 policy 误标 | provenance 失真 | 版本化 plan/model/map 并由 render 结果提供实际 policy。 |
| 新增插入与替换相互影响 | 非确定性 patch | 用 parent 作为 add 影响范围，拒绝任何嵌套或相同影响范围。 |
