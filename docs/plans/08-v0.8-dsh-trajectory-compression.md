# 实施计划：DSH 轨迹压缩与 Evolution Coding Agent 输入

> **阶段：**08 · **版本：**v0.8 · **状态：**已完成
>
> **依据规格：**[DSH 轨迹压缩与 Evolution Coding Agent 输入](../specs/08-v0.8-dsh-trajectory-compression.md)

## 1. 实施目标

在不执行真实 DSH、模型、Docker 或网络的前提下，实现本地、确定性的 `dsh-trajectory-compressed-v1` 生成链路。它消费已脱敏的 DSH JSONL 和既有 runner/evaluator 的公开 case 证据，生成仅供 Evolution Coding Agent 消费的受限输入；保留 v0.7 的 `trajectory.json` 报告兼容性。

本阶段只落地压缩、direct signal、agent-input artifact 与 Evolution 接线。不会调用 Coding Agent/LLM，也不会修改、导入、选择或晋级 candidate。

## 2. 实施方案与文件范围

```text
src/skill_evolve/
  trajectory/
    __init__.py              # 受限公共入口
    contracts.py             # 严格、冻结的压缩 artifact 与 agent-input 合同
    compressor.py            # JSONL 验证、稳定排序、跨 step 配对、截断与 direct signal
    policy.py                # 版本化阈值、错误模式、canonical policy hash
  benchmark/
    livesqlbench_rotation_run.py # 仅 Evolution 写 agent-input；Smoke/Final 不输出
  runner/
    dsh_session.py           # 暴露已脱敏 JSONL 的受限加载入口，不改变完成态 normaliser
tests/
  test_trajectory_compression.py
  test_livesqlbench_rotation_run.py
docs/specs/, docs/plans/, docs/design/
```

压缩器直接消费 `LoadedDshSessionLog` 或其已脱敏 JSONL 字节，不读取 session root、不解压 zstd，也不读取原始未脱敏日志。现有 `normalise_session_log()` 继续服务于完成态 runner；新的 loader/压缩路径允许解析有实质事件但没有 `turn/end` 的 partial timeout。

### 2.1 Artifact 与安全边界

1. `contracts.py` 定义严格 Pydantic 模型：source/policy 指纹、`complete | partial_actionable | partial_insufficient`、step、tool pair、direct failure、signals、candidate output、agent case bundle 和 compression diagnostics。
2. `policy.py` 定义所有固定上限、排序、redaction/路径角色化规则、错误分类和版本号；canonical JSON 的 SHA-256 写入每个 artifact。没有调用时钟、随机数或网络。
3. `compressor.py` 按原始 `seq`（缺失时输入顺序）稳定排序，使用 `(turn, call_id)` 跨 step 配对调用/结果；聚合事件优先，chunk 仅作明确 fallback。内部 reasoning 与 stream/UI 事件删除，未知类型、orphan result、missing result 和降级显式计数。
4. 所有可见 session/tool 文本先经过既有 credential redaction，再进行 custody path/Gold/GT 过滤、字段截断及 hash；输出字段带 `untrusted_evidence` 语义。SQL 只做 exact hash；不尝试不安全的 SQL 规范化。
5. `read`、`glob`、`pwsh`、`sql-readonly`、`web_search` 和 generic adapter 以固定规则提取有限信息；`web_search` 被视为允许的工具，保留有界公开检索摘要/结果 hash，不执行网络访问。

### 2.2 与 v0.7 运行的集成

1. 每个已执行 Evolution case，在 `_write_runner_artifacts()` 之后从本次 `RunnerExecution.raw_artifacts` 中定位对应的已脱敏 `dsh/<case>.session.jsonl`，而非扫描 run root。
2. 以可信 `LiveSQLBenchCase` 的 prompt/公开 context files、`RunSubject` binding、public evaluator projection 和 `RunnerCaseOutput` 构建 agent case bundle。实现不得序列化 `CaseEvaluation.expected_query`、Gold 执行结果、dump、GT 或绝对路径。
3. 对每个可解析 session 输出一个 compressed trajectory。`complete` 与 `partial_actionable` 一律进入 `agent-input/trajectory.json`；`partial_insufficient` 和无法解析的 session 只写无原文的 omission reason/quality state，且不当作 Coding Agent 证据。
4. 写入 `agent-input/manifest.json`，记录 `exposed_for_optimization: true`、当前 subject hash、Evolution manifest hash、policy hash、artifact hash 和 case count。此标记只记录数据暴露事实，不改变 v0.7 的 comparison key、Smoke gate 或 candidate 生命周期。
5. Smoke 继续可保存 custody evidence 和原 `trajectory.json`，但不得创建 `agent-input/`；Final 不使用该模块或输出逐题 artifact。

## 3. 有序任务

### 任务 1：建立 deterministic trajectory 合同和 policy

**依赖：**无。

**实施：**新增 `trajectory/contracts.py` 与 `policy.py`，用 strict/frozen Pydantic 定义 artifact、completion、signals 与 agent bundle；实现 policy 的 canonical JSON SHA-256、统一 UTF-8 JSON 序列化、固定字段与采样上限。

**验收：**同一输入和 policy 产生 byte-identical 输出；未知成本保持 `null`；任何不可见数据字段在类型上没有入口。

**验证：**纯内存 model/policy 测试；ruff、mypy。

### 任务 2：实现已脱敏 session 的有界压缩器

**依赖：**任务 1。

**实施：**在 `runner/dsh_session.py` 增加公共的已脱敏 JSONL 加载函数；新增 `trajectory/compressor.py`，验证 header/event/大小与类型，完成稳定步骤化、跨 step call/result 配对、assistant public text 提取、timeout completeness、usage、candidate output、unknown event 计数和 raw/compressed hash。

**验收：**内部 reasoning、chunk/UI 噪声不出现在输出；missing/orphan tool 结果不静默消失；没有终态但有公开行为时为 `partial_actionable`，仅启动事件时为 `partial_insufficient`。

**验证：**合成 JSONL 覆盖 completed、partial、跨 step、重复、unknown 与 malformed 负向 case。

### 任务 3：实现 adapter、redaction 与直接异常信号

**依赖：**任务 2。

**实施：**按固定 policy 为 `read`/`glob`/`pwsh`/`sql-readonly`/`web_search`/generic 解析 arguments/result，执行字段级截断、hash、credential/custody path 处理、稳定样例排序和 `untrusted_evidence` 包装；以多信号规则检测 `is_error`、`ok=false`、非零 exit code、结构化 status 和明确 SQL error pattern。

**验收：**`is_error=false` 加 `exit_code!=0` 仍被分类为直接失败；exit 0 的 warning 不误报；web search 保留固定、有界摘要而不被标为 policy anomaly；SQL literal/quoted identifier 不被不安全改写。

**验证：**合成 tool result、敏感文本、绝对 custody path 与 deterministic hash/ordering 测试。

### 任务 4：仅向 Evolution 输出 Coding Agent artifact

**依赖：**任务 1--3。

**实施：**在 `livesqlbench_rotation_run.py` 为 Evolution 生成 `agent-input/trajectory.json` 与 `agent-input/manifest.json`，使用内存中的 trusted case context 和本次 raw artifacts，不读取原始 session root。保留既有 `trajectory.json`。缺 session/解析失败仅在 manifest 记录 quality/omission，不改变 evaluator 结论；Smoke/Final 不写 agent input。

**验收：**passed、task failure 和 actionable timeout 都有可分析 case bundle；startup-only timeout 被排除；agent artifact 不含 expected query、Gold、GT、dump、凭据或绝对 path；旧 rotation 报告与 gate 语义不变。

**验证：**stub runner 测试有效 completed/partial JSONL，断言 Evolution 有且 Smoke 无 `agent-input`，并做泄漏断言。

### 任务 5：无模型回归、设计记录和索引收尾

**依赖：**任务 1--4。

**实施：**执行针对性测试、全量静态检查和无 Docker pytest；记录实际接口、已知限制、数据可见性和验证结果到 `docs/design/`，更新三个阶段索引为已完成。

**验收：**不存在真实 DSH/model/Docker/network 访问、自动 candidate 行为或 Final 逐题输出；设计记录不把未实现的 LLM 调用表述为已完成。

**验证：**

```powershell
uv run pytest tests/test_trajectory_compression.py tests/test_dsh_session.py tests/test_livesqlbench_rotation_run.py
uv run ruff check .
uv run mypy src
uv run pytest
git diff --check
```

## 4. 检查点

- [x] `dsh-trajectory-compressed-v1` 的 canonical serialization 和 policy hash 已锁定。
- [x] complete/actionable/insufficient 的分流仅依赖已观察事实。
- [x] tool adapter 的错误识别、截断和 redaction 有负向测试。
- [x] Evolution 的 agent-input 与 Smoke/Final 的不可见性有集成测试。
- [x] 设计记录只在实现和全部无模型验证完成后创建。

## 5. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| DSH event schema 漂移 | 误配对或丢失新 evidence | header/version 校验、unknown type counts 与 parser quality state，拒绝伪造解释。 |
| 大 tool output 淹没 agent context | 成本高、错误证据被掩盖 | policy 上限、稳定 sample、完整内容 hash 与失败调用 L2 保留。 |
| session 看似已脱敏但包含 custody 信息 | 泄漏到开发 agent | 二次字段 redaction、绝对 path 角色化、Gold/GT token 过滤和负向测试。 |
| 压缩失败改变评测结论 | 破坏 v0.7 的中性状态 | 只记录 compression quality/omission；runner/evaluator 状态仍由既有链路产生。 |
| 已见 Evolution manifest 被当成新证据 | 乐观偏差 | manifest 明示 `exposed_for_optimization`；不修改 existing comparison key，后续 candidate workflow 必须创建未暴露 manifest。 |

## 6. 不在本轮执行的事项

- 真实 Coding Agent/LLM 调用、prompt/provider/credential 配置或向外发送评测证据。
- candidate 草案自动导入、选择、promotion 或 rollback。
- 真实 DSH、真实模型、Docker fixture、网络检索、baseline、Final 执行或推送远端。
- 新 SQL dialect、并发、依赖、CI 或 custody/ACL 改动。
