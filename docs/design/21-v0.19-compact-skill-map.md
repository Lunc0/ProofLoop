# 实现记录：紧凑 SkillMap 与短编辑锚点

> **阶段：**21 · **版本：**v0.19 · **状态：**已完成
>
> **规格：**[紧凑 SkillMap 与短编辑锚点](../specs/21-v0.19-compact-skill-map.md) · **计划：**[实施计划](../plans/21-v0.19-compact-skill-map.md)

## 1. 实际实现

`build_skill_map()` 现在产生 `skill-map-v2`。Map 只收录 Markdown 的 `paragraph` 和 `list`，每个 block 使用按文档顺序分配的短 ID（`b01`、`b02`……），并保存 section、行区间、类型、layer 与 permission。

```json
{"block_id":"b26","section":"Error Recovery","block_type":"list","start_line":144,"end_line":147,"layer":"unknown","permission":"guarded"}
```

Map 不再保存 `SKILL.md` hash、逐块内容 hash、`block-<hash>` ID、完整祖先标题路径，或 frontmatter、heading、table、fenced code 的节点。既有标题分类白名单和 permission/layer 行为未改变；本阶段仅改变存储形式和定位 ID。

对没有段落或列表的极简 Skill，Map 可为空。它仍能作为 candidate 存储和 verify，但 optimizer 没有可用 target，因而不能产生可 materialize 的编辑。

## 2. 短 ID 的定位与绑定

optimizer 将 v2 Map 提供给 LLM。模型在 defect cluster 的 `block_ids`，以及 edit 的 `target_block_ids` 或 `placement_after_block_id` 中返回 `bNN`。EditPlan service 在生成时以本次父 Skill 的确定性 Map 解析这些 ID；renderer 再使用 block 的行区间定位原始 `SKILL.md` 的替换或插入位置。

`bNN` 不是跨版本标识。EditPlan source 仍保存父 candidate/Skill SHA-256 和 Map SHA-256，renderer 会先校验父 Skill bytes 及 Map binding。因此相同的 `b01` 在另一个 candidate 或 Skill 版本中不会被静默当成相同文本位置。

## 3. Candidate 存储与显式迁移

新 candidate 在 staging 时写入 v2 canonical `skill-map.json`。verify 根据候选的 `SKILL.md` 重建 canonical v2 Map 并与持久化文件逐字节比较；Skill 本身仍由既有 metadata/catalog 的 SHA-256 校验。Map 自身没有签名或额外 hash。

旧 v1 Map 不会通过 v2 verify。新增显式迁移命令：

```powershell
uv run skill-evolve candidate rebuild-skill-map <candidate-id>
```

它仅针对指定 candidate，从其现有 `SKILL.md` 原子替换 Map，再走常规 verify。普通读取、评测、optimizer 和 materialization 不会隐式迁移或修改 candidate。原有 `backfill-skill-map` 仍只负责为**缺失** Map 的历史 candidate 新建 Map。

已对本地 `dbhub/000-upstream-baseline` 执行 rebuild：其 Map 从 17,104 B 缩至 4,287 B；对应 Skill 为 7,748 B，Map 含 27 个 paragraph/list blocks，并已通过 candidate verify。

## 4. 兼容性

新的 EditPlan 使用 v2 的 `bNN` block IDs。既有 v1 EditPlan 仍属于原先 parent/Map 合同；本阶段不承诺可使用 v2 renderer materialize。`optimizer.__init__` 延续阶段 20 的懒加载导出，以避免 candidate store 使用 Map builder 时重新引入包初始化循环。

## 5. 验证

完成了无模型、无网络、无 Docker 的定向验证：pytest 覆盖 Map、candidate、EditPlan、renderer、materialization 与 CLI，共 43 passed、1 skipped（Windows 环境无法创建 symlink）；ruff、mypy 与 `git diff --check` 均通过。
