## 1. 实际实现

新模型响应的 `ModelSemanticEdit` 现在按 operation 校验文本落点：

- `add_rule` 只能使用一个 `placement_after_block_id`，不得携带 target；
- `clarify_rule`、`correct_rule`、`remove_rule`、`set_precedence`、`generalize_rule` 和 `reorder_workflow` 只能使用一个 target，且不得携带 placement；
- `merge_rules` 必须有至少两个 target，且不得携带 placement。

这只约束新模型响应。已绑定的 `SemanticEdit` 和 renderer 未收紧，历史 `add_rule` 的 target fallback 仍可读取和渲染。

trusted prompt 升级为 `skill-edit-plan-prompt-v4`，明确 cluster 是问题/证据单位，edit 是一次不可重叠的确定性文本变更。一个 edit 可引用多个兼容 cluster；一个 cluster 也可被多个位置互不重叠的 edit 引用。receipt 保持读取 v1-v3 prompt 的兼容，并记录新的 v4。

## 2. 安全与兼容边界

跨 edit 的 target/placement 不重叠校验保持不变；没有添加自动合并、隐式编辑顺序、自由文本 patch 或 LLM 二次修复。错误模型响应仍保留 raw response 并以 `invalid_response` fail closed。

未改变 candidate lifecycle、materialize、SkillMap、评测、真实模型调用或 CLI 行为。
