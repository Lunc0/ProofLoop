# 实现记录：EditPlan 位置语义与问题-变更分层

> **阶段：**22 · **版本：**v0.20 · **状态：**已完成
>
> **规格：**[阶段 22 v0.20 规格](../specs/22-next-edit-plan-location-semantics.md) · **计划：**[实施计划](../plans/22-v0.20-edit-plan-location-semantics.md)

## 1. 实际实现

新模型响应的 `ModelSemanticEdit` 现在按 operation 校验文本落点：

- `add_rule` 只能使用一个 `placement_after_block_id`，不得携带 target；
- `clarify_rule`、`correct_rule`、`remove_rule`、`set_precedence`、`generalize_rule` 和 `reorder_workflow` 只能使用一个 target，且不得携带 placement；其中 `reorder_workflow` 用其 `WorkflowRule` 文本替换完整 target block，而不是移动 block；
- `merge_rules` 必须有至少两个 target，且不得携带 placement。

这只约束新模型响应。已绑定的 `SemanticEdit` 和 renderer 未收紧，历史 `add_rule` 的 target fallback 仍可读取和渲染。

trusted prompt 升级为 `skill-edit-plan-prompt-v4`，明确 cluster 是问题/证据单位，edit 是一次不可重叠的确定性文本变更。一个 edit 可引用多个兼容 cluster；一个 cluster 也可被多个位置互不重叠的 edit 引用。receipt 保持读取 v1-v3 prompt 的兼容，并记录新的 v4。

## 2. 安全与兼容边界

跨 edit 的 target/placement 不重叠校验保持不变；没有添加自动合并、隐式编辑顺序、自由文本 patch 或 LLM 二次修复。错误模型响应仍保留 raw response 并以 `invalid_response` fail closed。

未改变 candidate lifecycle、materialize、SkillMap、评测、真实模型调用或 CLI 行为。

## 4. 后续小型修订：cluster 与 edit operation 解耦

cluster 继续只表达具体问题及其 case、evidence、Skill block 归因；edit operation 由目标文本变更决定，不再按所引用 cluster 的 `defect_type` 限制。target contract 继续完整提供给模型作为输入上下文，但 `contract_fields` 已从模型输出及绑定计划中移除；读取历史 bound plan 时会丢弃该退休字段。校验器只保留 edit 到 cluster 的 ID 关系，以及 edit、block、rule 的位置、权限、不重叠和敏感文本边界；不再使用 cluster 的 evidence、module 或 block 约束 edit。cluster 到 edit 的反向关系由 edit 引用推导。

renderer policy v2 将 `reorder_workflow` 收敛为可机械验证的整段替换：只接受一个可编辑 target block，以该 edit 的 `WorkflowRule` 生成的固定 Markdown 替换该 block。它不移动 block、不推断删除范围，也不执行隐式整篇改写；历史 provenance 的 policy v1 仍可读取。
