# v0.4：公开 PostgreSQL Benchmark Adapter

## 决策

v0.4 公开 `skill-evolve benchmark` 命令组，用于由受信任仓库代码实现的本地 PostgreSQL benchmark：

```text
skill-evolve benchmark validate <adapter-id> <data-root>
skill-evolve benchmark fixture-check <adapter-id> <data-root>
skill-evolve benchmark evaluate <adapter-id> <data-root> <runner-output.json>
skill-evolve benchmark run <adapter-id> <data-root> <dsh-manifest>
```

当前唯一 adapter 为 `livesqlbench-base-lite`。它迁移既有五题 LiveSQLBench Base-Lite 的 loader、
fixture、Soft-EX evaluator 和 DSH run 编排；`skill-evolve livesqlbench` 的四个命令保留为调用同一
adapter 的兼容入口。

Python 包版本为 `0.4.0`；v0.4 同时表示本次功能、设计和发布版本。

## 受控扩展点

`benchmark/contracts.py` 定义最小的 `BenchmarkAdapter` 协议：加载 suite、生成公开摘要、检查 fixture、
本地 evaluate，以及执行 DSH run。公开 suite 协议只暴露 adapter ID、公开摘要和源文件摘要；公开 run
结果只暴露 run ID、状态、attribution 和已脱敏 artifact 路径。

LiveSQLBench 的 case、Gold SQL、GT test cases 和 Gold 结果仍是 adapter 私有的进程内对象。它们不会成为
`RunInput`、`RunnerOutput` 或 contract 的公开字段。

`benchmark/registry.py` 是固定静态表，只导入仓库内的 `LiveSQLBenchBaseLiteAdapter`。它先验证小写
adapter ID，再解析已登记对象；未知或格式错误 ID 由 CLI 以用法错误码 64 拒绝。registry 不扫描数据目录，
不读取 import path，也不接受数据目录定义的命令、URL 或 runner 参数。

未来新增 benchmark 时，维护者必须在仓库中实现并审阅其 adapter，再显式加入 registry。新增 SQL 方言、
第二个数据集的授权或 GT 保管、并发、真实 DSH/模型调用、依赖或 CI 变更不属于 v0.4，需要单独确认。

## 数据与执行边界

LiveSQLBench data root 被当作不可信输入解析。loader 验证：

- public 和 GT 的 case ID 完全一一对应；固定的五个 approved Query case 均存在；
- database 与 dump 标识符安全；每个文件和目录引用在解析 symlink 后仍位于 data root 内；
- 每题的 schema、公开知识文件、table order 与 PostgreSQL dump 均存在。

每个 case 创建单独、可销毁的 PostgreSQL fixture；候选 SQL 由 fixture 的低权限 reader role 以只读策略执行。
DSH 每题只接收该题公开 prompt、schema、公开 context，以及只读本地查询 capability。为了保持 runner
contract 的形状，传给 DSH 的 `expected_query` 恒为 `SELECT 1`，而不是 Gold SQL。

评分仅在本地进程中执行，继续使用 LiveSQLBench 的 `conditions.order` 和 Soft-EX（注释、`DISTINCT`、
`ROUND` 与两位小数预处理）语义。`environment.json` 可包含源文件 SHA-256 digest，但不包含文件内容。

## 公开证据与失败处理

public stdout、agent workspace、DSH job、session evidence、runner output、evaluation、result 和 report
不得写入 Gold SQL、GT test cases 或 Gold 查询结果。持久化 evaluation 仅含 case ID、slice、verdict、
候选 SQL、公开 detail 和 usage；报告只使用公开 verdict 信息。

`DshRunner` 仍是唯一 DSH 子进程边界，使用 argv 和 `shell=False`。它既不依赖 adapter 类型，也不接收
来自 data root 的可执行配置。若 DSH timeout 或非零退出，runner 继续保存可读取且已脱敏的 changed
session log；无法捕获时保存单独的脱敏 capture-error artifact，而不会覆盖原始失败原因。

不连接生产数据库，不以高权限角色执行候选 SQL，不自动修改 Skill，也不在本阶段执行真实 DSH 或模型调用。

## 验证

v0.4 添加 registry、通用 CLI 等价性、GT-safe adapter serialization 和 public/GT case-ID 对应测试；既有
LiveSQLBench DSH-run 与 DSH timeout/非零退出 session-evidence 回归测试继续覆盖。交付前执行：

```powershell
uv run ruff check .
uv run mypy src
uv run pytest

```
