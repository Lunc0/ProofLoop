# 实现记录：Benchmark Runner Error 计为错题

> **阶段：**31 · **版本：**v0.29 · **状态：**已完成
>
> **规格：**[阶段 31 v0.29 规格](../specs/31-next-runner-error-as-incorrect.md) · **计划：**[实施计划](../plans/31-v0.29-runner-error-as-incorrect.md)

## 实际实现

`Verdict.RUNNER_ERROR` 现在是普通失败 verdict：`CaseEvaluation.passed` 为 false，attribution 将它和其他未通过题归为 `needs_skill_change`，而不再使 benchmark 暂停。

共享 LiveSQLBench 层新增受控 `RunnerError` 的最小 synthetic case：只有原本选中的 case ID、`runner_error` verdict 和固定诊断；没有 candidate SQL、原始异常、执行 artifact、usage、Gold、结果或虚构轨迹。Base-Lite、rolling 与 held-out loop 都在捕获该异常后写入该失败题并继续后续 case。fixture 异常仍使用既有 evaluator-invalid / paused 路径。

rolling Smoke、Evolution 和 Final 不再从统计中丢弃 runner error，也不再为它生成 `runner_invalid` 或 `partial_runner_error`。runner-error 题进入 `evaluations`、各 tier 的 evaluated 分母和 verdict aggregate；因此 run 状态按普通失败成为 `task_failure`。Smoke 仍只按通过题数写 gate，runner error 贡献零通过和一项已评测失败。Evolution 仍只把已有、安全且可压缩的 timeout session 送入 optimizer；无 `RunnerExecution` 的 synthetic error 只计分，不制造优化证据。`partial_evaluator_invalid` 和 `evaluator_invalid` 语义未改变。

## 安全与兼容边界

- 本阶段不会把 fixture、Gold preflight、GT、custody 或 `evaluator_invalid` 改算成错题。
- 公开 Base-Lite/rolling 结果及 held-out aggregate 不写入原始 runner exception；held-out case 证据继续只留在 custody。
- 既有 `runner_invalid` / `partial_runner_error` 仅作为旧 artifact 的读取兼容值保留在少数下游 guard 中；新的 rolling run 不再产生它们。
- 未运行真实 DSH、Docker、模型、网络或 benchmark。
