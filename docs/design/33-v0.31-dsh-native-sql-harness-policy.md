## 实际实现

数据库型 DshRunner 不再向 Agent workspace 写入 sql-readonly.ps1。Runner 先物化隔离 workspace 和
TASK.md 精确资源清单，再把仓库内固定的 sql_harness_policy.mjs 复制到 case-scoped runtime 目录并生成
额外 DSH patch。该 patch 只绑定 policy version、loopback query endpoint、精确资源路径和固定工具
allowlist；endpoint 不进入模型工具参数。

ESM 插件向 DSH 注册两个原生工具：

- sql_probe({query}) 调用现有 loopback ReadOnlyQueryService，成功或失败后仍处于探索阶段。
- sql_submit({query}) 使用同一只读执行路径；只有成功结果会把当前 Agent 切换到 FINALIZE。

插件在同步 agent/created 阶段将模型可见工具限制为 read、grep、sql_probe、sql_submit。Agent-scoped guard
进一步拒绝 allowlist 外工具、未在 TASK.md 精确列出的 read/grep 目标、已经成功的完全相同调用，以及
FINALIZE 后的全部后续工具调用。工具目录本身在会话中保持稳定，状态和成功调用 cache 不跨 Agent 共享。

## Runner 与证据合同

带数据库能力的运行现在必须配置并成功归档 DSH session。Session normalizer 从配对的 sql_submit
call/result 中只接受 ok=true、intent=submit、phase=finalize 的成功证据，并保存最后一条成功提交 SQL。
Runner 仍从最终 assistant message 的唯一 SQL fenced block 取候选，但在 evaluator 前要求它与成功 submit
一致；比较只规范化外围空白、换行和单个末尾分号。缺少 session、缺少成功 submit、缺失或多个 SQL block，
以及 submit/final 不一致均形成受控 runner_error。

每个 case 保存生成的 policy patch、policy version、固定 allowlist、资源列表和插件 SHA-256。插件 identity
也进入普通 DSH snapshot 及三条 LiveSQLBench environment fingerprint 路径。Trajectory compressor 将
sql_probe 和 sql_submit 映射到现有 sql-readonly adapter，并在 optimizer-safe projection 中保留
probe/submit intent；历史 PowerShell 和 sql-readonly evidence 合同保持兼容。

## 安全与兼容边界

- SQL 仍只经 disposable fixture 的非特权只读角色和现有单 statement policy 执行，没有 shell 回退。
- endpoint 只接受带显式端口、无 userinfo/query/fragment、精确 /query 的 loopback HTTP URL。
- 插件使用固定错误码；service 异常不会把 endpoint 或异常对象直接返回给模型。
- 没有 database access 的 DSH 路径不加载插件，继续允许现有 stdout candidate extraction。
- sql_submit 成功只表示候选在探索 fixture 上成功执行，不表示 evaluator 正确。
- 本阶段没有实现 optimizer 对 Harness Policy 的生成、修改、选择或晋级。

## 验证结果

离线 Python 定向测试覆盖 runner、session、轨迹压缩、projection、fingerprint 及三条 LiveSQLBench
fingerprint 调用路径。Node fake-runtime 测试覆盖工具注册、首请求前 restriction、资源 guard、重复调用、
submit 失败恢复、finalize 和 Agent 状态隔离。Ruff、mypy 与 git diff check 均通过。

本机安装的 DSH 版本为 0.1.1-rc.2。Synthetic patch 先经 dump-config 确认 overlay 组成，再从无项目
.env 的空目录执行 headless --help，退出码为 0，证明当前 DSH 可解析并加载插件进入 headless 应用。该检查
没有发送 DSH task。

验证没有调用模型、数据库、Docker、benchmark 或网络，也没有 commit/push。
