## 实际实现

rolling Evolution 在创建 run evidence 后、任何 DSH 或模型调用前，复用 trusted `LiveSQLBenchFixture` 和只读执行器对
冻结 manifest 的每个 Gold SQL 做预检。预检通过的 case 才会进入 DSH；无法执行的 case 只按脱敏错误类别计数，不写入
普通 run evidence、agent projection 或 optimizer 输入。预检 receipt 原子写入 rotation custody 的
`evolution-preflights/`，包含 run ID、manifest hash、evaluator 版本、selected/evaluable/discarded aggregate、类别计数
和 digest；不包含 Gold SQL、原始数据库错误、case ID 或 custody 路径。

`partial_evaluator_invalid` 表示至少一个 case 已被排除、且仍有可评估的 case。它的 `result.json` 只保留
`evaluator_preflight` aggregate；tier 评测数量不足时 macro average 与总 cost 为 `null`，并且没有 comparison key。
预检后运行阶段若又得到单 case `evaluator_invalid`，也会被排除并继续剩余 case。零个有效 case 保持
`evaluator_invalid`。Evolution 的单 case `runner_error` 会被排除；只要仍有有效评测 case 或可行动 timeout 轨迹，status 为
`partial_runner_error` 而不会中断 cycle。仅没有任何这类证据时才是 `runner_invalid`。

Evolution agent input 只从有效、失败且可压缩的轨迹生成。cycle receipt 新增可评估数和排除数的可选 aggregate；当 status 为
`partial_evaluator_invalid` 且至少有一个有效失败投影时，cycle 继续既有的 advice → EditPlan → materialization。若投影为空，
cycle 以 `no_optimizable_failure` 停止，且不调用优化 provider。Smoke 与 Final 的 fail-closed 行为没有改变。

v0.16 还将 Evolution 的 case 级 runner error 与结果隔离：DSH 超时且既有脱敏 session 成功压缩为 `partial_actionable` 时，
该轨迹可以进入 optimizer；其他 runner error 只记录并排除。非评分状态 `partial_runner_error` 没有 comparison key、完整 cost
或 macro score；result 仅增加被排除 runner error 与可行动 timeout aggregate。Smoke 与 Final 仍是 fail-closed。

## 兼容性与安全边界

- 既有完整 Evolution、Smoke、Final、candidate、DSH manifest 和 CLI 接口保持不变；新状态只扩展 Evolution 的结果合同。
- `runner_invalid` 和零有效的 `evaluator_invalid` 仍是 terminal；部分无效不是通过、分数或比较结论。
- 不修改 frozen manifest、reserve、Gold、GT 或官方数据；未增加 SQL dialect、并发、依赖、远端服务或自动 promotion。
- 公共 stdout、run/cycle receipt 和 optimizer 均只看到安全摘要，不能获得私有 Gold、case identity、数据库错误、路径或凭据。

## 验证结果

执行的是 fake fixture、fake DSH 和 fake optimizer 的无模型测试：

```powershell
uv run pytest tests/test_livesqlbench_rotation_run.py tests/test_evolution_cycle.py tests/test_optimizer_service.py
uv run ruff check .
uv run mypy src
git diff --check
```

覆盖了 Gold 预检排除后继续 DSH、零有效 case 不启动 DSH、部分无效且有有效失败时 cycle 继续、无有效失败时不调用优化器，
以及单 case runner error 被隔离后仍使用有效失败优化。没有运行真实 Docker preflight、DSH、模型、完整 benchmark、Final/held-out
或远端推送。结果：**23 passed**；Ruff 全量检查通过；mypy 对 **70 个 source 文件**通过；`git diff --check` 无错误。
