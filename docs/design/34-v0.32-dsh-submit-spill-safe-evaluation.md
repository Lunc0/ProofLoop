## 实际实现

`dsh_session.py` 不再要求 `sql_submit` 的 text block 必须整体恰好是一个 JSON document。新的窄 helper 使用
标准库 `JSONDecoder.raw_decode` 确定首个完整 JSON value 的边界：没有尾部时保持原合同；存在尾部时，仅接受
DSH 当前固定措辞的单行 spill notice，以及 Windows drive-absolute 或 POSIX absolute path。

notice 只用于确认尾部确实是 DSH transport/display 包装。解析器不会打开、搜索、stat 或持久化其中的路径，
也不会用 spill 文件补齐不完整 JSON。内联 JSON 必须自身完整，随后仍必须是 object，并继续满足既有
`ok=true`、`intent=submit`、`phase=finalize` 检查。

## Runner 与评测合同

修复后的链路仍是：

```text
sql_submit call/result -> 成功提交 SQL -> final/submit 绑定 -> candidate_sql -> Soft-EX evaluator
```

合法 spill notice 不再让 session normalization 提前产生 `runner_error`。最终 assistant message 含唯一 SQL
block 且与成功提交 SQL 一致时，`DshRunner` 产生 `status=completed` 和 `candidate_sql`，因此现有 evaluator
可以独立执行 candidate 与 Gold 并判断 `pass` 或 `wrong_result`。

任意普通尾随文本、第二个 JSON、畸形 notice、工具错误、非 finalize payload、缺失配对或 SQL 不一致仍失败
关闭。本阶段没有把 submit 执行成功当作答案正确，也没有改变 Soft-EX 或 runner-error 聚合语义。

## 安全与兼容边界

- session/tool result 继续作为不可信输入；只接受完整 JSON 加完整匹配的已知 notice。
- notice 中的路径不会被访问，也不会进入固定公开错误文本。
- 纯 JSON submit 和没有 database access 的现有 runner 路径保持不变。
- 没有新增依赖、数据库访问、shell 调用、网络调用或 DSH 全局配置修改。
- 合成测试只使用合成 SQL、空结果和不存在的临时路径，没有复制 held-out prompt、SQL、GT、结果行或 session。
