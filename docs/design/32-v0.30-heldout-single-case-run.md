## 实际实现

新增独立 CLI：

```powershell
uv run skill-evolve benchmark run-heldout-case `
  <data-root> `
  <dsh-manifest> `
  --case <exact-instance-id> `
  [--candidate <candidate-id>]
```

该命令加载和完整校验现有 `livesqlbench-base-lite-query-final-v1` manifest，再对 `--case` 做安全标识符
校验和精确匹配。未知、大小写不一致、路径式或不在当前 manifest 的值统一返回
`held-out case is unavailable`，不枚举有效 case。选择完成后只把一个 `CaseConfig` 交给现有 `_run_case`，
因此只建立该题所需的只读 PostgreSQL fixture、query service 和一次 DSH/model invocation。

`HeldOutCustody` 新增 `single_runs_root`。单题 service 以不可覆盖方式创建：

```text
<heldout-root>/single-runs/<YYYYMMDDTHHMMSSZ>-<instance_id>/
```

父目录必须是 resolved custody root 的直接、真实子目录；文件、symlink 和 Windows reparse point 均被
拒绝。目录名只使用 UTC 秒级时间戳和 manifest 已校验的 `instance_id`；同秒同题冲突时失败，不覆盖旧证据。
现有三十题路径继续使用 `<heldout-root>/runs/`，普通 workspace `runs/` 仍被 held-out adapter 忽略。

单题运行复用现有 runner artifact、Soft-EX evaluator、阶段 31 runner-error synthetic failure、subject
materialization 和 custody report。`run.json` 与 `result.json` 使用
`livesqlbench-heldout-single-case-v1`，并标记 `run_mode: single_case_diagnostic`。完整 case identity、prompt、
SQL、evaluation、attribution 和 runner evidence 只保存在 custody single-run 目录；DSH 的完整 session 继续写入
已强制校验的 `<heldout-root>/dsh-session-logs`。

## 公开结果合同

CLI stdout 和 `diagnostic-result.json` 只包含：

- suite ID 与 manifest SHA-256；
- subject binding 或 null；
- `single_case_diagnostic` run mode；
- run status 与 evaluated count；
- duration 和安全可取得的单题 cost。

公开 receipt 不包含 run ID、case ID、prompt、candidate SQL、逐题 verdict、原始异常、session 或 custody
绝对路径。单题结果不产生三十题分母、tier、macro average、Smoke gate、optimizer 输入或 candidate 生命周期
动作，因此只能用于诊断，不能称为 Final score。

## 失败语义与兼容性

- 受控 `RunnerError` 形成一条脱敏的 `runner_error` evaluation，公开 run status 为
  `needs_skill_change`，但异常原文不进入 receipt。
- fixture/Gold/evaluator 无效仍产生 `experiment_paused`，不改算为模型错题。
- 未知 case 和不安全 single-runs root 在 fixture、DSH 或模型调用前失败。
- `benchmark run livesqlbench-base-lite-query-final-v1 ...` 的三十题目录、schema、统计与公开 aggregate 未改变。
- 没有新增依赖、SQL dialect、并发、自动重试、优化或 Skill 修改。
