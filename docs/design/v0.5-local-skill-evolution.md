## 实际实现

阶段 05 建立了 Git 忽略的 `.local/skill-evolve/` candidate store。`catalog.json` 是可原子更新的索引；每个 candidate 目录只允许不可变的 `SKILL.md`、`metadata.json`，以及外部来源所必需的 `NOTICE.md`。候选文本和 metadata 采用 UTF-8、非空、512 KiB 上限；store 会拒绝目录、symlink、二进制、超限文件和任何额外附件。

`candidate.contracts` 提供 frozen Pydantic metadata/catalog，以及已校验字节的 `ResolvedCandidate`。解析 candidate 时，store 重新计算 `SKILL.md` SHA-256，交叉核对 catalog/metadata，并完整遍历同一 skill 的父谱系以拒绝缺失父项和环。所有 candidate ID、skill ID、run ID、来源仓库、commit 和 URL 都经受限格式验证；不会从 candidate、catalog 或 data 动态导入或执行代码。

## 公共命令与本地状态

`skill-evolve candidate init/import/list/show/verify/select` 已实现。`import` 需要现有的本地公开 run ID 和同 skill 的已验证 parent；`select` 仅原子更新 catalog 状态，绝不改写候选内容或 immutable metadata。候选命令不输出 Skill 正文；无效 ID、hash、谱系、文件或来源输入均以退出码 64 失败。

`init` 和 `import` 可同时携带 canonical HTTPS URL、来源仓库、40 位 commit、MIT license 和 notice 文件。若给出外部来源，五项必须完整，文件 hash 必须与 `SKILL.md` 一致，且 `NOTICE.md` 被强制保存。

本地已建立原始对照 `dbhub/000-upstream-baseline`：

- canonical URL：`https://github.com/bytebase/dbhub/blob/d91080ff9b3947de4de28095173fd4ec78a22f24/skills/dbhub/SKILL.md`
- commit：`d91080ff9b3947de4de28095173fd4ec78a22f24`
- `SKILL.md` SHA-256：`10019d4ed4a6cbcd12ae4652a4821f9f55059ba0ac55f770aea3daa2a604dc28`
- source repository：`bytebase/dbhub`；license：MIT；LICENSE 内容保存为该 candidate 的 `NOTICE.md`。

没有创建适配版：它必须由人工或外部上层 agent 提供新的单文件文本后，通过 `candidate import` 作为 `dbhub/001-livesqlbench-readonly-adaptation` 的 child 显式创建。

## 运行时绑定与隔离

普通 workflow 和 LiveSQLBench 都能接收 `ResolvedCandidate`。其 candidate ID/hash 进入环境 fingerprint、environment/run/result evidence，并以 `inputs/candidate-SKILL.md` 保存同一组已验证字节；`NOTICE.md` 永不进入 run input 或 agent workspace。

`benchmark run <adapter-id> <data-root> <dsh-manifest> --candidate <candidate-id>` 先解析并验证 candidate，再加载 adapter 或启动 fixture/DSH。LiveSQLBench 对每题继续创建独立 fixture 与 agent workspace；workspace 仅写入 `candidate/SKILL.md`、公开 schema/context、`TASK.md` 和既有 `sql-readonly.ps1` capability。固定 DSH job 与 `TASK.md` 都要求先读取 `candidate/SKILL.md`，且明确禁止执行、import 或加载其引用的代码。候选正文不会拼接进 DSH argv。

Gold SQL、GT tests/results、私有 dumps、数据根路径、凭据和未脱敏 session logs 未加入 candidate store、agent workspace、DSH job、stdout、公开 runner artifacts、evaluation、result 或 report。Base-Lite 仍由 adapter 本地以 Soft-EX 评分；其 PostgreSQL disposable fixture、只读查询和 timeout/非零退出时的脱敏 session-log 捕获保持原有实现。

## 兼容性与未实现项

原有 manifest candidate digest 和不带 `--candidate` 的 benchmark/LiveSQLBench CLI 仍可使用；Python 包版本保持 `0.4.0`。本阶段没有安装或启动 DBHub、没有加入 DBHub MCP、`search_objects` 或 `execute_sql`，也没有调用真实 DSH/模型。

阶段 D/E 未实施：没有自动 Skill 改写、反馈优化器、promotion/rollback、held-out gate、第二数据集、新 SQL dialect、并发、依赖、CI 或云存储。
