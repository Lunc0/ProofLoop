# 实现记录：Evolution 失败轨迹的依赖感知 Agent 投影压缩

> **阶段：**09 · **版本：**v0.8.1 · **状态：**已完成
>
> **规格：**[Evolution 失败轨迹的依赖感知 Agent 投影压缩](../specs/09-v0.8.1-agent-projection-evidence-compression.md) · **计划：**[实施计划](../plans/09-v0.8.1-agent-projection-evidence-compression.md)

## 1. 实际实现

v0.8.1 没有改写 `dsh-trajectory-compressed-v1`，而是新增 `evolution-coding-agent-input-v2`。v1 仍是包含 event location、hash、截断与配对信息的 custody 审计 artifact；v2 从 v1 的受限、已配对 evidence 生成，交给 Skill Optimizer 的 `agent-input/trajectory.json` 不再带上述审计 metadata。

`run_rotation_dsh_suite()` 仍只在 Evolution 的 `CaseEvaluation.passed == false` 分支调用 session 压缩和 v2 输入组装。builder 也拒绝把 `verdict == "pass"` 的 trajectory 放进 v2。全通过 Evolution run 因而输出合法的空 `trajectories`，没有 `omitted_cases` 字段。失败但没有可安全投影 session 的数目只留在 custody `agent-input/manifest.json` 的 aggregate `omitted_case_count`，不生成 Optimizer case。

`CompressorPolicy` 的 projection-only 字段不进入原来的 `policy.sha256`。因此变更 v2 的文本/数量上限不会改变相同 v1 审计轨迹的 source policy fingerprint 或字节内容。

## 2. v2 合同与证据优先级

v2 顶层一次性声明 `session_derived_evidence_untrusted: true`，并只包含 rule version、environment fingerprint、subject ID、受限 Skill 文本和失败 `trajectories`。每个 case 包含：

- 可信且有界的 prompt、固定 task contract、difficulty 和选取后的 public context；
- 按 P0–P3 稳定排序的 `evidence`；
- 仅 runner 实际接受的 `candidate_output.sql`；
- 无 candidate 时独立的 `final_submission_attempt`，其 fenced-SQL 提取状态绝不冒充已提交 SQL；
- agent-safe evaluator verdict、candidate、detail 与 usage。

P0 包括 tool failure 和不完整 trace；candidate/final attempt/evaluator 作为 case 的独立 P0 结构保留。失败 evidence 有 action、直接错误类别/原因、bounded error 和“后面是否有同 adapter 成功调用”的事实标记；该标记不宣称业务上的根因已修复。

成功 `glob` 只有在后续出现成功 `read` 时压成不含路径列表的 `workspace_discovery`；失败 glob 不会折叠。read 使用安全 target 与“已反映于上下文/有界 evidence”的事实，不重复交付整段正文。所有投影文本均有固定 UTF-8 上限。

## 3. 直接引用与 SQL 边界

`trajectory.dependency` 是本地、无依赖、fail-closed 的 tokenizer。它跳过 string literal、line/block comment 和 dollar quote，安全处理 quoted identifier，并提取 Query-slice 中 `SELECT`、`WITH [RECURSIVE]`、CTE、derived/nested subquery、`FROM`/`JOIN`/`LATERAL`、filter/group/order/limit、set operation、aggregate 与 window 的直接 table、qualified-column 和 clause facts。真实 DSH 的 PowerShell 调用 `.\sql-readonly.ps1 -Query '…'` 或双引号等价形式也会提取其中的 SQL；不能明确识别时输出 `sql_unparsed`，不建立猜测 dependency。

sample rows 的降级刻意更小：只接受无 CTE、subquery、set operation、window、group/having 或 `EXPLAIN` 的扁平 limited `SELECT … FROM/JOIN … WHERE … LIMIT`；后续 `COUNT`/`MIN`/`MAX`/`SUM`/`AVG` 必须有相同 relation/join/filter token scope，且覆盖同一 qualified field。filter scope 会保留 string、dollar-quoted 与 numeric literal，以及比较/算术等 operator；因此不同筛选值或运算符不能被误判为同一数据范围。满足时 sample 的 rows 被替换为 coverage fact；任一不确定或字段不匹配时 rows 仍保留。没有 SQL 语义等价判断。

schema 目前安全选择简单 `CREATE TABLE …;` block、SQL 直接引用的 table 和一跳 FK endpoint。knowledge/column-meaning 支持 JSON list/object、JSONL 和逐行文本；只在 public assistant text、SQL/tool argument、candidate/final attempt 或 evaluator detail 中直接匹配 record 的 `id`、`key`、`name`、`title` 或 `code` 时选择。没有高置信直接命中或不支持格式时输出受限 fallback，而不称未选内容为无关。

## 4. 保管与兼容性

- v1 合同、canonical compression、原始 redacted session 保留、Smoke gate、Final custody、evaluator、candidate lifecycle 和 comparison key 未改变。
- v2 `trajectory.json` 不含 `sha256`、seq、timestamp、event/call/result location、绝对 custody path、expected query/result、GT/Gold 或逐字段 untrusted/hash/truncation metadata。审计需要的 hash 继续位于 v1 与 custody manifest。
- 只使用公开 session text 与 public context；不调用模型、Optimizer、真实 DSH、Docker、网络或 benchmark run。投影规则没有任何业务实体名称。
- DDL/SQL/JSON 无法安全解析时优先保留有界 fallback，避免因压缩把不确定信息判为无关。

## 5. 验证

执行了以下无模型、无网络、无 Docker 的验证：

```powershell
uv run pytest tests/test_trajectory_compression.py tests/test_trajectory_projection.py tests/test_livesqlbench_rotation_run.py
uv run ruff check .
uv run mypy src
git diff --check
```

结果：定向 pytest **14 passed**；ruff 通过；mypy 对 **53** 个 source 文件通过；`git diff --check` 通过。测试使用合成 JSONL、context 和 stub runner，覆盖 v1 fingerprint 不变、全通过不进入 v2、v2 无 hash/GT、PowerShell SQL 提取、引用提取与更严格的 sample 覆盖（包括筛选值和运算符）、KB/schema/FK 选择、workspace discovery 折叠、失败/后续同工具成功、final submission attempt 以及 rolling runner 写入。

未运行完整 pytest（避免可能触发 Docker 标记用例），也未运行真实 DSH、模型、baseline、Evolution 或 Final。实施后若要人工评估压缩率，可由用户在已授权的 custody 环境比较数个已脱敏 Evolution session 的 raw/v1/v2 本地大小和证据完整性；比较明细不得进入 Git、stdout 或 Optimizer 输入。
