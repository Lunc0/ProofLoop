# 实现记录：候选内置 SkillMap

> **阶段：**20 · **版本：**v0.18 · **状态：**已完成
>
> **规格：**[候选内置 SkillMap](../specs/20-v0.18-candidate-owned-skill-map.md) ·
> **计划：**[实施计划](../plans/20-v0.18-candidate-owned-skill-map.md)

## 1. 实际实现

每个新 candidate 在 local store staging 目录中从已验证的 `SKILL.md` 字节调用既有确定性
`build_skill_map()`，并原子写入以下文件：

```text
SKILL.md
skill-map.json
metadata.json
NOTICE.md                  # 仅 external candidate
```

`skill-map.json` 使用 canonical JSON，并保留既有 `skill-map-v1`、`skill-map-policy-v1`、Skill SHA-256、block
行区间、类型、权限和 ID。candidate metadata 未新增 Map hash 或签名字段。

读取 candidate 时，store 将 Map 作为允许文件的一部分，拒绝缺失、symlink、非 UTF-8、非法 JSON/schema、无效 policy 或
Map 内 Skill hash 与实际 `SKILL.md` 不一致的情况。除这个基本一致性校验外，本 MVP 未引入额外认证、签名或远端验证。

## 2. 历史候选回填

新增显式命令：

```powershell
uv run skill-evolve candidate backfill-skill-map <candidate-id>
```

该命令临时允许被验证的历史 lineage 缺少 Map，拒绝覆盖已有 Map，只写入由当前 `SKILL.md` 本地生成的
`skill-map.json`，随后按常规路径重新 verify。普通 `verify`、`select`、评测和 optimizer 不会隐式回填或修改候选。

已对本地 `dbhub/000-upstream-baseline` 执行该命令，生成了与其
`10019d4ed4a6cbcd12ae4652a4821f9f55059ba0ac55f770aea3daa2a604dc28` Skill hash 绑定的 Map。

## 3. 兼容性边界

本阶段没有改变 optimizer 的 Map 输入来源：它仍对 run materialized subject 即时确定性建图，并保留成功时在 run
`optimizer/edit-plan/` 发布 snapshot 的既有行为。candidate Map 是创建后可审阅的持久副本；无效模型响应只清理 run 的
EditPlan artifact，不会影响 candidate 中的 Map。

candidate store 为复用 MVP Map builder 直接引用 optimizer 的 Map 模块。该引用暴露出 package 初始化循环，因此
`optimizer.__init__` 改为懒加载公开导出，避免 candidate/registry 启动时加载依赖 candidate 的 materialization 服务。
这是导入边界修复，不改变公开导出的名称或模型调用行为。

## 5. 后续边界

metadata 内 Map hash/policy binding、提取共享 Map 模块、以及让 optimizer 直接读取 candidate Map 均未纳入本 MVP；它们需要
后续规格明确后再实施。
