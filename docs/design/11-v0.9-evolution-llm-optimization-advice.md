# 实现记录：Evolution 后 LLM 优化建议 MVP

> **阶段：**11 · **版本：**v0.9 · **状态：**已完成
>
> **规格：**[Evolution 后 LLM 优化建议 MVP](../specs/11-v0.9-evolution-llm-optimization-advice.md) · **计划：**[实施计划](../plans/11-v0.9-evolution-llm-optimization-advice.md)

## 1. 实际实现

v0.9 在既有 Evolution rolling run 的末尾加入一次可选的、只给建议的 LLM 调用。
它不是新的 CLI 命令：同一次 Evolution 运行在写入 `agent-input/`、计算既有 benchmark
status 后，按 manifest 中的 `environment.optimizer.enabled` 自动决定是否调用。

`OptimizerConfig` 默认禁用，并固定为 DeepSeek `deepseek-v4-flash`、环境变量引用
`DEEPSEEK_API_KEY`、30 秒 timeout、2,000 token 输出上限和
`skill-optimization-advice-prompt-v1`。该引用只保存变量名；运行时才读取其值，任何
optimizer artifact、环境快照、结果或异常中都不保存密钥。

在进程环境没有非空同名变量时，client 只从当前工作目录 Git 忽略的 `.env` 读取这一键；它不加载或
导出 `.env` 的其他键，也不修改 `os.environ`。`.env.example` 提供无值模板。此规则只适用于本地
optimizer，未改变 DSH credential store 与 held-out 的凭据边界。

生产 client 使用标准库 `urllib.request` 对 DeepSeek Chat Completions 发出一次非流式
POST。请求固定为 JSON Object 输出、关闭 thinking 且没有 `tools` 字段。client 可由
`OptimizerClient` protocol 替换，故测试全部使用 fake client 或 fake HTTP transport。

## 2. 准入与数据边界

优化服务只在 Evolution path 调用；Smoke、Final、held-out 和普通 benchmark adapter
不会进入该服务。即使在 Evolution，runner/evaluator invalid、未启用、v3 artifact 缺失或
无效、Skill SHA-256 不一致以及没有失败 trajectory 都不会访问 provider。

服务只从当前 run 下读取 `agent-input/manifest.json` 与
`agent-input/trajectory.json`。它拒绝 symlink 或越出 run 目录的路径，验证
`evolution-coding-agent-input-v3`、`exposed_for_optimization: true`、canonical JSON
SHA-256、输入大小以及 evaluated Skill binding。提示将通过验证的 v3 payload 标为不可信；
它不会读取 `raw/dsh/`、原始 stderr、GT、Gold、custody 路径、凭据或其他 run artifact。

模型必须返回受限的 `skill-optimization-advice-v1` JSON。服务校验 case ID 只能引用输入中
的失败 case，并拒绝额外字段、重复 case ID、NUL、超限文本与以 `# SKILL` 开始的完整
Skill 文档。来源 binding 由服务本地添加，而非采信模型声明；持久化 advice 仍标记
`model_output_untrusted: true`。

## 3. Artifact 与评测隔离

成功时当前 run 写入：

- `optimizer/advice.json`：带本地 `source` binding、模型摘要和建议片段的严格 JSON；
- `optimizer/advice.md`：供人工查看的 Markdown 片段；
- `optimizer/receipt.json`：terminal status、非机密 provider/model/prompt 版本、可用时的
  usage、输入/建议 SHA-256 与错误代码。

任何 terminal path 都会写最小 receipt。根 `result.json` 只增加 status、`advice_path` 和
非机密 provenance，不复制建议正文。`proposed`、`skipped_no_failed_trajectories`、
`skipped_invalid_evidence`、`model_failed`、`invalid_response` 与 `unavailable` 均与
benchmark status 分离；它们不会改变分数、gate、comparison key 或已有 evidence。

建议不会创建、改写、导入、选择、晋级或回滚 candidate，也没有 provider 重试、工具调用或
agent loop。

## 4. 配置与兼容性

已有 manifest 未配置 `environment.optimizer` 时会得到 disabled 默认值，保持原有运行行为。
启用配置的非机密形式见 [配置说明](../configuration.md#evolution-自动优化建议v09)。
optimizer 配置会写入本次 run 的 `environment.json` 供审计，但不会参与 DSH model route、
Evolution comparison key 或评测指标计算。

manifest 密钥检查改为路径白名单：仅
`environment.optimizer.api_key_env` 和 `environment.optimizer.max_output_tokens` 可以包含
敏感关键字片段。后者避免把普通输出 token 上限误判为 token 凭据，同时没有放宽其他位置
的 secret 拒绝规则。

## 5. 验证

完成了无模型、无网络、无 Docker 的验证：

```powershell
uv run pytest -m "not docker"
uv run ruff check .
uv run mypy src
git diff --check
```

结果：pytest **109 passed, 1 skipped, 5 deselected**；唯一跳过项是 Windows 环境无法创建
symbolic link。Ruff 通过；mypy 对 **58** 个 source 文件通过；`git diff --check` 没有空白
错误（仅 Git 行尾转换提示）。新增测试覆盖缺失 key 不发请求、固定 DeepSeek JSON 请求、
provider 非成功响应、v3 hash 篡改、raw session 不进入 prompt、无失败跳过、非法 case
binding，以及 Evolution 成功/失败时的自动编排和 result 摘要。

没有执行真实 DeepSeek 请求、真实 DSH、Docker、数据库、baseline、Evolution 或 Final，
也没有导入 candidate 或推送远端。

## 6. v0.9 补充：已完成 run 的显式建议

新增 `skill-evolve optimizer advise <run-id>`。它打开当前工作目录 `runs/` 下既有目录，
要求 `run.json` 与 `result.json` 都绑定
`livesqlbench-base-lite-evolution-v1`，并且 result status 是已完成的 Evolution terminal
status。随后从 `inputs/subject.json` 和 `inputs/subject-SKILL.md` 重建并验证 subject；
symlink、目录逃逸、缺失或无效 binding 都在 provider 调用前拒绝。

命令显式代表一次 operator 请求，因此使用固定 `OptimizerConfig(enabled=True)`，不要求
历史 manifest 已经启用 optimizer。它复用相同的 v3 hash/size/subject 准入与无工具 client，
但不启动 benchmark、DSH、fixture、evaluator、Docker 或第二个 run。完成后将最新 receipt
摘要写回既有 `result.json`，stdout 仅有 run ID、status、相对 advice path 和非机密
provider/model/prompt 标识。

CLI 测试通过 fake advice service 验证：命令不会创建第二个 run、不会输出 materialised Skill，
并且非 Evolution 或缺少 subject 的 run 在调用 provider 前以 usage error 拒绝。
