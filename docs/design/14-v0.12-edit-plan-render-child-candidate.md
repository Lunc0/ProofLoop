> **计划：**[实施计划](../plans/14-v0.12-edit-plan-render-child-candidate.md)

## 1. 实际实现

v0.12 新增显式命令：

```powershell
uv run skill-evolve optimizer materialize <run-id> --candidate-name <child-name>
```

它只读取一个既有、完成的 Evolution run；不调用优化模型、不启动 DSH、不连接数据库，也不重跑任何 benchmark。成功时，
它把 run 中 `optimizer/edit-plan/edit-plan.json` 渲染为单文件 `SKILL.md` unified diff，并通过 local candidate store
原子创建一个 `draft` child。

阶段 13 的 `guarded` 仍表示 Purpose/Activation/未知旧章节等需要保守定位的区域，但不再要求人工审批。新 plan 对 guarded
edit 直接使用 `proposed`；历史 artifact 的 `requires_guarded_approval` 仅在 materialization 读取时归一为 `proposed`，
新写路径不再产生该状态。`locked` 仍不可渲染。

## 2. 模块与合同

- `optimizer/edit_plan_contracts.py`：新 plan terminal status 只保留 `proposed`、`findings_only` 与失败状态；
  `normalise_historical_edit_plan_status` 是读取旧 guarded 状态的唯一兼容边界。
- `optimizer/edit_plan_renderer.py`：`skill-edit-render-policy-v1` 用 rule definition 的四种类型生成确定性 Markdown，
  输出 `a/SKILL.md` 到 `b/SKILL.md` 的 unified diff。后续 policy v2 将 `reorder_workflow` 收敛为单个 workflow
  block 的整段替换，而非猜测重排结果；v1 provenance 保持可读取。
- `optimizer/materialization_contracts.py`：冻结 receipt、source binding 与 terminal status；成功 receipt 绑定 run、
  parent、EditPlan、target contract、patch、child hash 和 edit 数量。
- `optimizer/materialization_service.py`：验证 plan/run/parent binding、目标区块存在且非 locked、patch 可回放到 exact
  parent，并发布本地 evidence 后创建 child。
- `candidate/contracts.py`：增加 `CandidateOrigin.OPTIMIZER` 与可选 `OptimizerProvenance`；历史 v1 metadata 仍可读，
  candidate 目录仍仅允许 `SKILL.md` 与 `metadata.json`。

## 3. 持久化与输出

成功 materialization 产生：

```text
optimizer/
  edit-plan/                 # 既有阶段 13 artifact，不修改
  materialization/
    rendered.patch
    receipt.json
```

根 `result.json` 使用 `optimizer_materialization` 摘要键，仅记录状态、相对 patch 路径、parent/child ID、child/patch hash
和 edit 数量。stdout 使用同一摘要，不输出 Skill、patch、EditPlan、case、evidence、GT、Gold 或凭据。

child metadata 中的 `optimizer_provenance` 保存 EditPlan SHA-256、patch SHA-256、parent Skill SHA-256 和 render policy
version；child 始终是 `draft`，不会被选择、评测、晋级或回退。

## 4. 机械边界

- renderer 仅使用 parent bytes 与已绑定的 `SemanticEdit`，不读取 trajectory、session 或模型输出以外的数据。
- parent 与 child 必须为 UTF-8、无 NUL；patch 必须非空、相对路径固定为 `SKILL.md`，并能从 exact parent 回放出 exact child。
- 每个变更必须来自一个 plan target 或 anchor；locked target、未知 block、重叠范围、patch 标记、private path 或
  secret-like child 文本均 fail closed。
- 不可由固定模板表达的 edit 返回 `render_failed`，不退化为整篇重写。

## 5. 验证结果

在合成 run、fake candidate store 和本地 CLI runner 上执行：

```powershell
uv run pytest tests/test_materialization_contracts.py tests/test_materialization_service.py tests/test_materialization_cli.py tests/test_edit_plan_renderer.py tests/test_edit_plan_contracts.py tests/test_edit_plan_service.py tests/test_candidate_store.py tests/test_edit_plan_cli.py tests/test_optimizer_cli.py
uv run ruff check .
uv run mypy src
git diff --check
```

结果为 **33 passed，1 skipped**（Windows 环境未提供可用的 symlink 创建能力）；Ruff 通过；mypy 对 **67 个 source
文件**通过；`git diff --check` 无空白错误，仅有 LF/CRLF 转换提示。

没有调用真实模型、DSH、Docker、数据库、Smoke、Evolution、Final 或 held-out，也没有创建真实 candidate 或修改本地
candidate store。
