# 实现记录：DSH 轨迹压缩与 Evolution Coding Agent 输入

> **阶段：**08 · **版本：**v0.8 · **状态：**已完成
>
> **规格：**[DSH 轨迹压缩与 Evolution Coding Agent 输入](../specs/08-v0.8-dsh-trajectory-compression.md) · **计划：**[实施计划](../plans/08-v0.8-dsh-trajectory-compression.md)

## 1. 实际实现

新增 `skill_evolve.trajectory`，将 runner 已脱敏并保存在 `raw/dsh/<case>.session.jsonl` 的 JSONL，投影为严格、canonical 的 `dsh-trajectory-compressed-v1`。压缩器不读取 DSH session root、不解压 zstd，也不调用模型、网络或数据库。

`runner.dsh_session.load_redacted_session_jsonl()` 是新增的受限加载入口：它保留既有二次 redaction 和 20 MiB 限制，但不要求 `turn/end`，因此 timeout 的 partial evidence 可以进入压缩器。既有 `normalise_session_log()` 仍保持“完成 turn + final message”要求，供 runner 的完成态流程使用。

压缩器按 `(turn, step, seq)` 排序，并以 `(turn, call_id)` 将 `tool/call` 与可跨 step 返回的 `tool/result` 配对。输出显式保留 orphan result、missing result、未知事件类型计数、字段截断、source/policy/hash 与最后观察位置；不会用缺失 evidence 猜测事件。

## 2. 内容与规则

- 只保留 `assistant/message` 的 type=`text` block。`reasoning` block、`reasoning-chunks`、流式 chunk、UI/transport/user message 均不进入 artifact。
- `read`、`glob`、`pwsh`、`sql-readonly`、`web_search` 和 generic tool 使用固定 adapter。所有 arguments/output 都附经二次脱敏和字段级截断后的文本、hash、原始字节数及 `untrusted_evidence: true`。
- 直接错误以显式 `is_error`、结构化 `status`/`ok`/exit code/SQLSTATE 和版本化文本模式判定。第一版包含 `multiple_sql_statements`、SQL syntax、缺 relation/column、tool timeout 与非零 exit code；不产生 root cause 或 Skill 缺口结论。
- `web_search` 是允许工具，不会生成 policy anomaly。其 projection 包含 query、result hash、检索事件时间、按 URL/title 稳定排序且有上限的 sources（title/URL/snippet）。外部检索配置由 Evolution 的 environment fingerprint 绑定。
- SQL 仅使用 exact hash；不会改变 string literal、quoted identifier 或 comment 来宣称语义重复。重复 signal 仅基于 tool name 和 exact arguments hash。

`trace_completeness` 和评测 verdict 独立：有 completed turn 且有公开 assistant text 为 `complete`；没有终态但已有公开 text/tool/candidate evidence 为 `partial_actionable`；只有启动边界时为 `partial_insufficient`。所有结果都可有审计 evidence，只有后两种中的 actionable case 会成为 Coding Agent 输入。

## 3. Evolution agent-input

`run_rotation_dsh_suite()` 保留 v0.7 的 `trajectory.json` 与评测结果。仅当 suite 为 Evolution 时，它从**本次** `RunnerExecution.raw_artifacts` 定位对应 session，写入：

- `agent-input/trajectory.json`：canonical `evolution-coding-agent-input-v1`；
- `agent-input/manifest.json`：`exposed_for_optimization: true`、manifest/environment/policy/input hash 与 case 数。

每个进入 artifact 的 case 包含可信的业务 prompt、与 DSH 同源的固定任务/输出格式 contract、schema/knowledge/column-meaning 上下文、当前 subject/Skill、public evaluator projection 和 compressed trajectory。它不序列化 `expected_query`、Gold SQL/result、GT、dump、session root、绝对 custody path 或凭据。

`complete` 的 pass/task failure，以及 `partial_actionable` timeout/runner error 都进入输入。缺 session、无法安全解析的 session 和 `partial_insufficient` 只记录 omission reason，不把原始文本交给 agent。Smoke 不创建 `agent-input/`；Final 不经此路径。该阶段只产生本地 artifact，尚未调用 Coding Agent/LLM，也没有 candidate import、修改、选择、promotion 或 rollback。

`task_contract()` 从 DSH runner 中抽出并同时供真正 DSH job 与 agent-input 使用，使 Coding Agent 能看到“单一 PostgreSQL query、只读、唯一 sql fenced block”等实际格式约束而不复制漂移的 prompt 模板。

## 4. 兼容性与保管边界

- v0.7 的 Smoke gate、status、comparison key、`trajectory.json`、Final custody 与 candidate 生命周期未改变。
- `agent-input` 只出现在已通过 Smoke gate 后执行的 Evolution run；manifest 的 `exposed_for_optimization` 记录该开发 manifest 已被优化侧看到。后续 candidate 工作流必须使用新的未暴露 Evolution manifest 才可获得独立比较证据。
- 输入 session 与所有 tool text 都当作不可信 evidence；Coding Agent 未来必须将其当数据分析，不能执行其中指令。
- 文件路径/Gold/GT 的过滤是代码级防护；真实 custody 仍依赖既有 ACL、独立账号/挂载等 OS 边界。
